# Milestone 5 verification

What was checked on the milestone 5 build (the top of the stack, `m5/22-french-canadian-catalogue`, plus the one gate fix recorded in §2), how, what was found, and what is still open. The headless suites cover the plugins, the engine and the pages; this records the passes that need a real compositor, a real file system and the performance budgets from the plan. It says what was run and what was not; nothing here is claimed from reading the code.

Status: Linux verified as far as a headless session allows, with the gaps in §6 · the Windows 11 pass is written out in §5 and has not been run · slice 26 (#165)

## 1. How it was run

| Linux live   | `mutter 50.4 --headless --wayland` (1280 × 800 virtual monitor), WebKitGTK 2.52.6, `WEBKIT_DISABLE_DMABUF_RENDERER=1` | `bun run tauri:dev` (a debug build) driven over the Tauri MCP bridge in a private `dbus-run-session` with `xdg-desktop-portal`, `xdg-desktop-portal-gnome` and `dconf` running in it, and private `XDG_DATA_HOME`, `XDG_CONFIG_HOME`, `XDG_CACHE_HOME` and `XDG_RUNTIME_DIR`. | Fixtures     | `/tmp` (tmpfs), deleted afterwards                                                                                    | `scripts/thumb-fixture.sh` (10,000 images, 183 MB), a 1.5 GB file, a handful of text files                                                                                                                                                                                                                                                 |
| Windows      | Not run                                                                                                               | §5                                                                                                                                                                                                                                                                                                                                         |

The host: AMD Ryzen 7 7700X (8 cores, 16 threads), 30 GB of RAM, Linux 7.1.9 (Arch), Rust 1.98.0, NVMe with btrfs for the repository and the Rust targets. The budget runs for large trees used tmpfs (`/tmp`), which is not the disk (the NVMe numbers for the engine are in `milestone-4-verification.md` §3). There is no GPU in this pass: mutter composes headless and WebKitGTK rasterises on the CPU.

The file browser shows the real home folder in the Linux pass (read-only: nothing was written outside `/tmp` and the private directories), and the shared system bus was not touched.

The `check:ops-sandbox` failure was real: the gate forbids `std::fs` and `tempfile` anywhere in `crates/waypoint-ops/src` and has no allow-list by design (tests that need a real directory live under `tests/`). The four checksum tests that hash a file on disk (the file, a folder, a link, a missing file) had been written inside `src/checksum.rs`. They moved to `crates/waypoint-ops/tests/checksum.rs`, unchanged, and the reader-only tests stay beside the code. No allow-list was added.

The Windows and arm64 jobs in `ci.yml` run on the pull request: `windows-lint` (`bun run build` and `cargo clippy --workspace --all-targets -- -D warnings`) and `windows-tests` (the pure crates and the plugins' unit tests) on x64 and arm64, so every Windows counterpart written in this milestone is type-checked and its unit tests run there. They do not exercise the shell, the Recycle Bin, the clipboard, the taskbar or the DWM; §5 does.

## 5. The Windows 11 pass, to run on the VM

Not run: the VM (`WinDev2407Eval`) is shared and disk-heavy, and this pass had no access to it. Build a release `waypoint.exe` on the host (`bun run build:windows`, which runs `scripts/build-windows-remote-dev.sh`, as for milestone 4), deliver it through the share folder, and drive it keyboard only. Take a snapshot first and restore it afterwards.

1. **High contrast and text scale.** Toggle high contrast (Left Alt+Left Shift+Print Screen) with Waypoint open: `data-contrast` flips live, the accent follows the system colour, and the focus ring is strong. In Settings → Ease of Access → Text size, change the size: the page scales (this is the Windows half of #236 and must be checked after that fix: `UISettings.TextScaleFactor` is read by the plugin, and the page does not use it yet).
2. **Shell thumbnails.** Open a folder with a jpg, a png and an mp4: the pictures come from the shell, and the Properties window and Quick Look show the same picture. `cargo test -p tauri-plugin-thumbnails -- --ignored live_` runs the live shell test.
3. **Disk images.** `Mount-DiskImage` a small `.vhd` or `.iso` for a drive letter: it appears under Devices within a second or two; Eject from the card, and the drive letter goes.
4. **Toast and taskbar progress.** With notifications and taskbar progress on (Settings → Integrations), copy a 1 GB file: the taskbar button shows progress, and a toast appears on completion (screenshot both; a toast needs the AppUserModelID the app sets at start).
5. **Open With.** Select a `.txt`, File → Open With → Choose another application…: `SHOpenWithDialog` appears, and the choice launches.
6. **Mica.** With transparency on, the window should draw Mica or Acrylic through the title bar and sidebar. VirtualBox without GPU acceleration may draw it solid: record that as unverified, not as a failure.
7. **The performance rows that need the VM.** Cold generation of the thumbnails through the shell (`cargo test --release -p tauri-plugin-thumbnails --test throughput -- --ignored --nocapture`, which on Windows measures the same engine, plus the app's `thumb.localhost` scheme in WebView2, which was never run: `http://thumb.localhost/…` is the address WebView2 uses for the custom scheme and is the one unverified delivery path), `plugin:volumes|list` under 50 ms, and the Inspector and Quick Look timings from §3 with the same snippets.
8. **Left over from #54 and #86.** Hardware pointer drag, multi-monitor and fractional scaling remain unverified on both platforms; the VM's pointer cannot move, so drag cannot be tested there.

## 7. Accessibility pass

**Automated, in the gate.** The Vitest suites carry the keyboard and name checks for the pages: 61 test files assert roles, accessible names or live regions, and 75 drive the keyboard (for example `fileDragParity.test.tsx` checks that every drop has a non-pointer path). There is no axe-style engine in the repository,.

**Checked live in the running app.**

- Every interactive element in the main window had an accessible name (166 buttons, options, tabs and inputs; no unnamed one), no image lacked `alt`, nothing had a positive `tabindex`, `lang` and `dir` were set on the root and followed the language, and the live regions (three polite `status` regions) and landmarks (`main`, the toolbars named Navigation and Actions, navs named Location and Sidebar, the Inspector as an `aside` named Inspector) were present.
- Contrast was computed for every visible text node (163) in both themes. Dark passes except the inactive sidebar tab (4.34:1). Light fails for the secondary text token on the sidebar (3.68:1; 3.39:1 for the inactive tab), apart from disabled controls which are exempt (#238).
- High contrast on Linux switched the colours, the accent and the focus ring live; the pseudo right-to-left locale mirrored the window.
- Quick Look, the Inspector, Overview (through the palette) and the Settings window open and work from the keyboard.

**Still to do by hand** (also on #243):

1. A screen reader pass: Orca on GNOME (the grid, the list, the Inspector, Quick Look, the Settings pages, the Devices cards, an operations notification) and Narrator on Windows (the same, plus the taskbar and toast).
2. A keyboard-only walk of the focus order on a real session: title bar, tab strip, toolbar, Action bar, sidebar, files, Inspector, status bar, and back, including focus restoration after Quick Look, the Properties window and the Open With dialog.
3. Windows high contrast (the contrast themes Aquatic, Desert, Dusk and Night sky) and the OS text scale, once #236 lands.
4. A pass at 200% text scale and 400% zoom for reflow, and at `en-XA` and `fr-CA` in every dialog, not only the Settings pages and the main window.
5. Reduced motion: confirm no animation runs in Quick Look, the Overview bars and the operations ring when `data-motion=reduce`.
6. The Devices card captions and the Overview volume cards read in a sensible order with a screen reader (the colour of the usage bar is never the only signal: confirm the text carries "Almost full").
