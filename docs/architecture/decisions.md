| A18 | Accepted (2026-09-30) | **Milestone 0 spikes 1 and 5 results and the rules they set**: 60 Hz scrolling, instant jumps and near-instant selection on a 500 000-row listing in WebKitGTK (Wayland and XWayland), and 500 000 entries scanned in about 0.6 s over a `Channel`. | A32 | Accepted (2026-09-30) | **`waypoint-path` holds the platform rules as pure functions, and locations use a lossless `file://` URI.** `VfsPath` is scheme-shaped with only `file` implemented; `FilePath` wraps the native path. The Linux rules (`posix`, over bytes) and the Windows rules (`windows`, over strings: drive letters, UNC, `\\?\` long paths, device paths, reserved names, case folding) are compiled on every platform, so both are unit-tested on Linux. Normalisation is lexical (it resolves `.` and `..` without touching the file system); verbatim paths are taken literally. A Linux name that is not UTF-8 survives through percent-encoded bytes in `Location.uri`; `display` is lossy. Drive paths are `file:///C:/a`, UNC paths `file://server/share/a`, and verbatim or device paths use the empty-authority form `file:////%3F/C:/a` so the prefix survives the round trip. A Windows name with an unpaired surrogate is not representable (`PathError::Unrepresentable`). Property tests are hand-rolled from a fixed seed rather than adding `proptest`. | The same `Location` must name any file the provider can list (A19), and Windows rules that only run on Windows would be the first thing to regress (A11).                                                                                                                                                                                                                                                                                                                                                                                                                 |
