# Milestone 6 verification on Windows 11

What was checked on the milestone 6 build of `main` on Windows 11, how, what was found, and what could not be checked. It is the Windows counterpart of `milestone-6-verification.md` and follows its method: it says what was run and what was not, and nothing here is claimed from reading the code. #310, part of #308.

Status: one pass on the Windows dev VM, keyboard and a click helper only, on 2026-10-06 · the app starts only with the fix in #501 · six defects filed (§4) · Git, resume, cancel, thumbnails, Narrator and SMB against a server not run (§5)

## 1. How it was run

| What     | Where and how                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Guest    | VirtualBox `WinDev2407Eval`, Windows 11 Enterprise Evaluation 22621, 4 CPUs, 8 GB, 175 % scaling, run headless (screenshots from VirtualBox, not from the host's display); Rust 1.98.0 (MSVC) and Bun 1.4.2                                                                                                                                                                                                                                                                                                                                                                             |
| Build    | `main` at `bbbd0386` (Open a dragged place or folder in a new pane, #494) exported with `git archive` and copied to `C:\work\waypoint`; `bun install --frozen-lockfile`, `bun run build:plugins`, `bun run --cwd apps/waypoint build`, `cargo build -p waypoint --features tauri/custom-protocol` (a debug build with the frontend embedded), `CARGO_INCREMENTAL=0`                                                                                                                                                                                                                     |
| The app  | Started on the interactive desktop from `cmd`, its log sent to a shared folder. There is no Tauri MCP bridge on Windows, so it was driven by the keyboard and, where a click was needed, a small PowerShell helper that moves the window so the target sits under the guest's pointer (pinned at the centre of the screen) and presses the button there; nothing could be dragged                                                                                                                                                                                                       |
| Servers  | On the host, bound to `127.0.0.1` and reached from the guest at `10.0.2.2` through VirtualBox NAT, each with credentials generated for the run and stopped afterwards: OpenSSH `sshd -D` as the current user on port 22322 (the configuration of the SFTP provider's test harness, `UsePAM no`, `StrictModes no`, key login only, a second host key for the changed-key check); `rclone serve webdav` on 28089 (basic authentication); `rclone serve s3` on 28090 (an access key pair). No SMB server: Samba on port 445 needs root, and the Windows SMB client cannot use another port |
| Fixtures | Served from one host folder: 6 images, 10,000 and 100,000 empty files, a 64 MiB random file, two small text files. In the guest under `C:\wpv`: `sample.zip`, `sample.tar.gz`, `sample.7z`, an encrypted zip (`zip -P`), `unsafe.zip` (`../evil.txt`, `CON.txt`, `trail. `, `a:b.txt`), a copy of `sample.zip` to write to, a folder nested past 260 characters (336), and files named `CON`, `aux`, `NUL.txt`, `trail.` and `space ` made through `\\?\`                                                                                                                               |
| Profile  | The guest had no Waypoint data, no `known_hosts` and no Waypoint credentials before the run. `APPDATA` and `LOCALAPPDATA` cannot redirect the app (it asks Windows for the known folders), so the real profile was used and everything the run created there (both `ca.liminalhq.waypoint` folders, `~\.ssh\known_hosts`, the credential, the two archives in the Recycle Bin, `C:\wpv`) was removed afterwards                                                                                                                                                                         |

The first build attempt stopped when the host's disk holding the VM filled; the build that ran was partly warm from it, so its times are not a cold build: the frontend steps took 70 s, `cargo build` 3 min 07 s, and the rebuild with #501 applied 1 min 51 s.

## 2. The startup crash

The build of `main` panics before its first window:

```
thread 'main' panicked at …\tao-0.37.1\src\platform_impl\windows\window.rs:1145:41:
OleInitialize failed! Result was: `RPC_E_CHANGED_MODE`. Make sure other crates are not using multithreaded COM library on the same thread or disable drag and drop support.
```

just after `system-appearance` logs "cannot listen to high-contrast changes: Element not found. (0x80070490)" twice. This is the crash #501 fixes, and #501 is still open. Its diff (`0127f8bf`) was applied to the guest's copy only (one import hunk in `plugins/system-appearance/src/palette/windows.rs` by hand, since `main` has moved), and with it the app started every time. Every result below is from that build.
