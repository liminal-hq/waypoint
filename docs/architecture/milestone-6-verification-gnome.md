# Milestone 6 verification on a live GNOME desktop

What was checked on `main` (up to #553, with every milestone 6 fix through #547 to #553 merged) in a real, logged-in GNOME Shell session rather than the headless compositor of `milestone-6-verification.md`, how, what was found, and what is still open. It is also the accessibility and performance pass of #311 as far as one Linux desktop can take it. It says what was run and what was not; nothing here is claimed from reading the code.

Status: one pass on GNOME Shell 50.4 under Wayland, time-boxed to about 90 minutes · KDE Plasma, Cinnamon, Windows 11 hardware and a spoken screen reader session not run · #311

## 1. How it was run

| What          | How                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Desktop       | The maintainer's own GNOME Shell 50.4 session (mutter 50.4, Wayland), WebKitGTK 2.52.6, Linux 7.1.9. Two 3840 × 2160 monitors at 150 % (2560 × 1440 logical each). GTK theme Mint-Y-Dark-Red, icon theme Mint-Y-Red, `color-scheme` prefer-dark, accent red. The host is the one in `milestone-5-verification.md` §1 (Ryzen 7 7700X)                                                                                                                                        |
| Builds        | A release build (`bun run build:plugins`, `bun run --cwd apps/waypoint build`, `cargo build --release -p waypoint --features tauri/custom-protocol`) for the timings, and `bun run tauri:dev` (debug, with the MCP bridge) for everything else                                                                                                                                                                                                                              |
| Isolation     | Private `HOME`, `XDG_DATA_HOME`, `XDG_CONFIG_HOME` and `XDG_CACHE_HOME` under `~/.cache/waypoint-live-gnome` (the real Waypoint settings were not touched); `XDG_CONFIG_HOME/dconf` pointed at the real dconf database so GTK read the real theme. A private `ssh-agent` and a private `~/.ssh/known_hosts`. No password was saved, so the login keyring was never written; the keyring itself was not tested                                                               |
| Input         | Real pointer and keyboard events through mutter's own `org.gnome.Mutter.RemoteDesktop` and `ScreenCast` D-Bus API (a remote-desktop session with a stream of one monitor, `NotifyPointerMotionAbsolute`, `NotifyPointerButton`, `NotifyKeyboardKeysym`). GNOME asked for no consent for a session on the session bus. Before each press or key the focused frame was read through AT-SPI and the event was dropped unless it was a Waypoint window (or the helper Nautilus) |
| Timings       | The page's own harness (`apps/waypoint/src/dev/perfHarness.ts`, built with `VITE_WAYPOINT_PERF=1`), driven by a local, uncommitted change that opened a list of folders one after another and logged a `PERF_RESULT` line for each; first rows and full counts timed with `requestAnimationFrame` from `tabsApi.navigate`. Start-up timed from `exec` to the window's AT-SPI frame and to its first list rows. Memory is RSS and PSS of the app and its WebKit processes    |
| Accessibility | The AT-SPI tree of the Waypoint windows read from Python (`gi.repository.Atspi`), as Orca would see it. GNOME's high contrast, text scaling and animation keys were changed with `gsettings` and put back as they were                                                                                                                                                                                                                                                      |
| Servers       | User-level OpenSSH `sshd` on 127.0.0.1:2232 and `rclone serve webdav` (no authentication) on 8088, each behind a Python TCP proxy adding 50 ms each way (100 ms round trip) on 2233 and 8089                                                                                                                                                                                                                                                                                |
| Fixtures      | `~/.cache/waypoint-live-gnome/fx` on the NVMe disk: 10,000 and 100,000 empty files, 2,000 PNG images (256 × 192), a folder of common file types, archives and a Git repository; everything deleted afterwards                                                                                                                                                                                                                                                               |

## 3. Results by area

| Area                                              | Result                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

| 1. Look and feel                                  | **pass**: the window follows the dark scheme; the window controls sit on the right in GNOME's minimise, maximise, close order (`button-layout` `appmenu:minimize,maximize,close`), round Adwaita-style buttons in the Settings window. Theme source System took GNOME's red accent; Match the system's colours drew the real Mint-Y-Dark-Red palette (window `#2e2e33`, selection `#841316`, focus ring `#e7384b`) in the open main window at once. Icon theme System drew Mint-Y-Red folders and type icons for text, JSON, HTML, PNG, shell and zip; the Waypoint theme its own. Transparent window turned the root translucent while the window had focus and solid when it lost it; the Transparency page says "GNOME does not let apps blur behind their windows". High contrast followed GNOME's `high-contrast` key. What the desktop looks like through a translucent window was not looked at (it would mean a screenshot of other windows). Portage was not looked at                                                                                                                                                                                                                                                                                                                                                                                                                               |
| 2. Drag and drop, real pointer                    | **partly**. In the window: a row dragged with the real pointer said "Dragging notes.txt", "Over Videos: will move" and so on for each folder passed, sprang Documents open after a hold ("Opened Documents") and moved the file there. Tear-off: dragging a pair's tab out of the window made a new window that followed the pointer through `xdg-toplevel-drag` ("Moved Split: … to a new window", `ToplevelDragEnded … DroppedElsewhere`), and dragging it back onto the first window's strip merged both tabs and closed the emptied window (`DroppedOnWindow … region: strip`, "Moved 2 tabs to this window"). A tab dropped on the content area split the view, as SPEC says. To Nautilus: a row dropped in a Nautilus 50 window copied the file ("Dropped data.json in another application"). From Nautilus: a file dropped on a Waypoint pane copied it ("Over Documents: will copy", "Copied from-nautilus.txt"). Defects: Shift during a drag in from Nautilus still copied (#567); Shift during a drag out ended the drag silently and left every later drag out refused with "an outbound drag is already active" (#566). The Shelf, a drop between two Waypoint windows and drops into a remote tab were not run                                                                                                                                                                                  |
| 3. Notifications, sleep, dock progress            | **partly**: with Notify when a job finishes on and every Waypoint window minimised, a copy that met an existing folder sent `org.freedesktop.portal.Notification.AddNotification` titled "Copy “f100k”", "Waypoint is waiting for your answer.", default action `raise` and one button **Show**. A 10.1 s copy with the window in front sent none, which is the 10 s rule. Keep the computer awake took a GNOME session inhibitor "Waypoint is working on files" through the portal for the job and released it at its end. Show progress on the app icon sends `com.canonical.Unity.LauncherEntry` updates, which stock GNOME does not draw (a dock extension does). Clicking a notification button was not run: GNOME draws the banner over the maintainer's other windows, so a blind click there was not safe                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| 4. Screen reader tree and keyboard                | **partly** (from AT-SPI, no speech): the main window has a `main` landmark, `page tab list` "Tabs" whose tabs carry the path or the pair as description and `selected`, toolbars "Navigation" and "Actions", `navigation` landmarks "Location" and "Sidebar" with a "Sidebar view" tab list, and status bars. The file list is a `list box` "Files", `multiselectable`, of about 30 `list item`s for a 10,000-entry folder, each with `posinset` and `setsize` 10000 and the `selected` state, and `get_n_selected_children` agreed. The Settings window has a `navigation` "Settings sections" and a `main` named by the page. Focus returned to Connect to Server… when the Connect dialog was cancelled. Text scaling followed GNOME at 1.5 and 2.0, but the sidebar's names grew about twice as much as everything else and were cut off (#568). GNOME's Reduce Animation did not reduce motion (#569).
