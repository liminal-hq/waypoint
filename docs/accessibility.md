# Accessibility and Focus Review

Status: prototype review, 2026-09-29. Findings are from reading the markup and behaviour. The AT-SPI tree of the main and Settings windows was read on a live GNOME desktop in milestone 6 (`architecture/milestone-6-verification-gnome.md`), which is what Orca reads, but no screen reader has spoken it yet.

## What is in place

- **Landmarks:** the tab strip is a tablist (each tab has aria-selected), the toolbar is a toolbar, the sidebar is a navigation region, the file area is the main region, and the status bar is a polite live region.
- **Menu bar and Action bar:** the application menu is a menu button (`aria-haspopup`, `aria-expanded`) opened by F10, a lone Alt or Alt plus F, E, V, W or H (F10 and a lone Alt toggle it, so pressing either again closes it), with arrow keys, Escape and focus returning to the button; disabled rows are `aria-disabled` with the reason as their title. The Action bar is a `toolbar` with a roving tab stop (Left, Right, Home, End), its buttons are 28 px targets named by their label (also when labels are hidden), a disabled button stays focusable, is `aria-disabled` and is described by its reason, and it moves its trailing buttons into a More menu rather than clipping them. It only transitions when motion is allowed.
- **Command palette (milestone 4, slice 20):** a native modal `dialog` named “Command Palette” holding a `combobox` (`aria-expanded`, `aria-controls` the list, `aria-activedescendant` the active option, `aria-autocomplete="list"`) and a `listbox` of `option`s with `aria-selected`; focus stays in the field while the arrow keys, Home, End, PageUp and PageDown move the active option, and typing always goes to the field (Tab moves nothing). An option is named by one sentence (“Move to Trash, File, shortcut Delete”, with “on” or “off” for a setting and “unavailable: reason” for a disabled command), and the match is bold as well as the active row outlined, so neither is shown by colour alone. A polite live region reads the count (“12 commands”, “No commands match”) and, for Enter on a disabled command, the reason. Esc, a click outside and the window losing focus close it and focus returns to where it was; a command that moves focus (Rename) runs after that, so it keeps it. Animation is off under Reduce motion. The key is Ctrl+Shift+P, which does not clash with text editing.
- **Git status (milestone 6):** nothing Git shows is shown by colour alone. A row's Git cell draws letters (`M`, `A`, `D`, `R`, `T`, `?`, `!`, `U`, hidden from assistive technology as symbols) and a dot, with the same thing in words beside them for a screen reader and as the tooltip: "Modified, staged; Modified, not staged", "Untracked", "Conflict", "3 changed items inside, 1 in conflict", "Git repository"; the colour (warning, success, danger, muted) only repeats the letters, and an ignored item is dimmed and also says "Ignored". The grid has the same marks as a chip at the corner of the item. The Git column heading is a sort button like the others, with the sort direction spoken, and the header's menu (right-click, the menu key or Shift+F10 on a heading) is a `menu` named "Columns" with one checkbox, "Git status", that opens on its first item with the keyboard and returns focus to the heading. The branch item in the status bar is a `group` named "Git branch" whose text is the sentence a screen reader reads ("Git repository waypoint, on branch main. 2 commits ahead of the upstream branch. A merge is in progress. 1 in conflict, 2 not staged"), with the visible text (`main ↑2 ↓1` and a dot) hidden from assistive technology so it is not read twice; it is not a live region, so a branch that changes under a running window is not announced unprompted. The sidebar's dots say how many items changed inside the place. The Inspector's Git tab is one more tab of the same tablist (it is absent, not disabled, outside a working tree, and the panel falls back to Preview when it goes away) with a `tabpanel` named "Git" of labelled rows and an ordered list of commits; it holds no button, its loading and failure messages are `status` text, and the history is read only after the selection has held still, so a held arrow key announces nothing. The column and its menu entry, the sort entry and the status item are not there outside a working tree, so nothing is announced for a folder with nothing to say. Checked under `en-XA` (the column holds its width and the heading is not clipped) and `ar-XB` (the column follows Name on the other side, and the chip sits at the item's other corner), which use logical properties throughout.
- **Administrator Mode (milestone 9, #440):** an elevated tab is marked in words as well as colour. Its tab has a shield and the word "Administrator" in its details (read with the tab and shown in its tooltip, as "Pinned" is) and `data-elevated`; the title bar has a button named "Administrator" described as "Leave Administrator Mode", which runs that command; the window's title ends "— Administrator" (so the app switcher and the task bar say it too); and the window's edge carries a frame in `--wp-elevated`, a token that is at least 4.5:1 against the window colours in light, dark and high contrast. While the system's prompt is up a polite status line reads "Waiting for the system’s prompt…" beside a real Cancel button, and nothing in the window is blocked. A folder that needs approval is a `role=alert` with Authenticate and Leave Administrator Mode buttons; a refusal is said in text ("Authentication was cancelled or refused"). Delete there asks in a dialog that says it is permanent, as an administrator, and cannot be undone, whatever the Trash confirmation setting is.
- **Keyboard:** every action has a keyboard path (see the shortcut list, press ?). Shortcuts can be rebound in Settings → Keyboard, with conflict detection.
- **Focus:** a setting turns on a thick, always-visible focus ring.
- **Motion:** a setting turns off all animation and transitions, including drag feedback.
- **Contrast:** a high-contrast setting strengthens borders and lifts muted text. Transparency keeps a solid backing behind text.
- **Touch:** touch mode raises rows, buttons and menu items to at least 44 pixels; Auto turns it on in narrow windows.
- **Text size:** Default, Large (115%), Larger (130%), or the system's text scale when that is larger (`--wp-text-scale` on the root). Every `font-size` is `calc(Npx * var(--wp-text-scale))`, so all text grows by the factor once (`inherit` takes its parent's already scaled size and is never scaled again); `theme/textScaleCss.test.ts` fails on a fixed size. Fixed-height chrome can clip at the largest scales.
- **Names that tell controls apart:** the file lists of the panes of a pair are named "Files, pane 1 of 2: {title}" and "Files, pane 2 of 2: {title}" (a single tab's list is "Files"). The Connect dialog's More options is a button with `aria-expanded` and `aria-controls`, not a `details` element, which WebKitGTK does not expose to a screen reader as a disclosure.
- **Direction:** right-to-left mirrors the window, tabs, sidebar and back/forward arrows. `lang` and `dir` are set on each window's root from the language (Settings → Language & region; the Direction row can force either way). Layout uses CSS logical properties (`margin-inline-start`, `inset-inline-end`, `text-align: start`), enforced by `scripts/check-logical-css.sh`, which lists the places where physical is right with a `physical:` comment (the tab drag pill and split zones that follow the pointer, the context menu's viewport placement). Directional glyphs (back, forward, the small chevron, undo, redo, copy to, move to, the sidebar glyph) carry `data-directional` and flip under `dir=rtl`; a glyph that means a physical side, such as the tab strip's scroll buttons, opts out.
- **Arrow keys follow the direction:** in a right-to-left layout Left is forward and Right is back in the grid and grouped lists, the folder tree (Left opens a folder), the Action bar, tabs and groups (including Ctrl+Shift+arrow reorder), Quick Look, and menus (Left opens a submenu), as they already did in the Inspector, the Shelf, pane dividers and segmented rows. Handlers use `isRtl` and `inlineKey` in `i18n/direction.ts`. Scrollers use `scrollLeft` as signed in right-to-left.
- **Addresses stay left to right:** addresses, URLs, paths and host names are left-to-right content in any layout. The Connect dialog's Address, Host, Port, User and path fields and the path bar's text field have `dir="ltr"` (a connection's name keeps the direction of its own text), and an address shown beside other text (a saved connection's address, a breadcrumb, a host key's host and fingerprints, the branch in the status bar) is a `<bdi>` through `Ltr` or `Own` in `apps/waypoint/src/i18n/bidi.tsx`, so a parenthesis or a colon next to it does not move in a mirrored layout. A value put inside a translated sentence or a title goes through `isolateLtr` or `isolateOwn`, which wrap it in Unicode isolates only while the window is right to left.
- **Resizing the list's columns:** each column but Name has a divider on its start edge that is a focusable vertical `separator` named "Resize the Size column" (the heading is the column's own), with `aria-valuenow`, `aria-valuemin` and `aria-valuemax` in pixels and a value text ("88 pixels wide"). Left and Right resize it by 8 pixels and Shift by 32 (Left widens in a left-to-right layout and Right in a right-to-left one, as the divider moves toward the start edge), Home and End go to the narrowest and widest, Backspace or Delete restores the column's own width, and the header menu's _Reset Column Widths_ (reached with the menu key or Shift+F10 on a heading) restores every column. A divider is a sibling of the sort button, never inside it, so a drag cannot sort. A run of key presses is kept once, when the keys rest or the divider loses the focus, and nothing is announced beyond the new value.
- **Resizing the list's columns:** each column but Name has a divider on its start edge that is a focusable vertical `separator` named "Resize the Size column" (the heading is the column's own), with `aria-valuenow`, `aria-valuemin` and `aria-valuemax` in pixels and a value text ("88 pixels wide"). Left and Right resize it by 8 pixels and Shift by 32 (Left widens in a left-to-right layout and Right in a right-to-left one, as the divider moves toward the start edge), Home and End go to the narrowest and widest, Backspace or Delete restores the column's own width, and the header menu's _Reset Column Widths_ (reached with the menu key or Shift+F10 on a heading; listed disabled when no column of the folder is resized) restores every column of the folder shown. The widths are the folder's own, like its view and sort, so a folder opens with the widths set in it. A divider is a sibling of the sort button, never inside it, so a drag cannot sort. A run of key presses is kept once, when the keys rest or the divider loses the focus, and nothing is announced beyond the new value.
- **Checking a layout:** a developer build offers the pseudo-locales `en-XA` (accented, 30% longer, `[` `]` markers) and `ar-XB` (right to left); choose `ar-XB` and look for anything that did not mirror, or clipped text under `en-XA`. Reordering tabs by dragging is not yet mirrored in a right-to-left layout; the keyboard reorder is.

## Still to do (found in this review)

1. **File rows need roles.** Rows are plain elements. Give the list role=listbox with aria-multiselectable, each row role=option with aria-selected, and announce the selection count.
2. **Menus.** Context menus need role=menu and menuitem, arrow-key focus, and to return focus to the trigger on close. The optional menu bar (Settings → General → Title bar) is a `role=menubar` of `menuitem` buttons with `aria-haspopup="menu"`, `aria-expanded` and `aria-keyshortcuts` (Alt+F, E, V, W), and one tab stop. Left, Right, Home and End move along it, Down, Enter or Space open a menu with its first row focused, and Escape closes it with focus back on its button; while a menu is open Left and Right switch to the neighbouring one. F10 or a lone Alt focuses the first menu and, pressed again or followed by Escape, returns focus to the element it came from. It collapses into a More menu rather than clipping, and its background transition is off under reduced motion. While it is shown the title bar's app name is plain text, not a second menu button. With Settings → Experimental → Native context menus on (D196), the file list, sidebar, Trash and tab context menus are the system's own menus, so their roles, names, arrow-key navigation, type-ahead, `Esc` and the exposure to assistive technology are the platform's, not the page's ARIA (the menu's `ariaLabel` is not passed on), and the focus returns to the row, item or tab that opened it; the Menu key and Shift+F10 still open them at the focused row. This is unverified with Narrator and Orca, and the menu bar, app menu, title-bar menus, the menus a button opens, the Shelf and the drop action picker stay in the page.
3. **Dialogs.** Give them role=dialog with a label, trap focus, and restore it on close. Escape already closes them.
   - The shared `Dialog` (`docs/shared-components.md`) gives role=dialog (native) named by its title, focus into the dialog on open (never on a destructive button), a Tab and Shift+Tab trap, Esc, focus restored to the opener, and a non-dismissible mode for questions that must be answered.
   - Checklist for each dialog the app builds on it: the title says what the dialog is about; destructive confirmations use `ConfirmDialog` with `danger`; a dialog that cannot be dismissed offers a visible way out or an answer to every question; stacked dialogs return focus to the one beneath.
   - Help and its siblings (Help, Keyboard Shortcuts, Take the Tour, About): each is the shared `Dialog`, so it traps focus, closes on Esc and returns focus to where F1, `?` or the menu was used; moving from Help to a sibling hands the return focus on, so the last close lands back at the opener. Help starts on Close. The picture is decorative (`aria-hidden`) and stops moving under reduce motion, with the mark resting in the middle of the route; the rows are lists (`ul` with an accessible name), each key a real `kbd`, and the shortcut list has one named list per group. The tour's step line is a status region, so Next and Back announce “Step 2 of 5” while focus stays on the pressed button. Rows grow to 44 pixels for a coarse pointer, take system colours with a visible border under forced colours, and use logical properties so right-to-left mirrors them (the picture's route stays left to right). `?` and F1 are not bound while a dialog of another kind is open, and `?` is ignored in a text field.
   - Conflict and error dialogs (milestone 4, slice 09): the conflict dialog is a `role=dialog` named by its count and destination, with a table (caption, column headers, each name a row header) whose choice selects are named “Choice for {name}” and described by what the choice does, so the danger of Replace is said in words (“Replaces the whole folder…”) as well as styled. Nothing is pre-selected; Continue is a disabled button until every clash is answered, and a polite status line (“2 of 4 answered”) says how far the answers are. Focus starts on the first control (the bulk choice, empty), never a destructive one. Escape closes the dialog and leaves the job waiting, exactly like Decide later; “Cancel the operation” stops the job, behind a confirmation whose default focus is “Keep deciding” once anything was answered; a click outside does nothing. The error dialog is named “An item could not be processed” (or “The original folder is gone”), describes the problem as its description, starts on Retry (Recreate folders for a missing folder), never on Skip all like this, and keeps checksums behind a disclosure; the item and job lines are selectable text. After Continue the live region says what will happen (“Continuing: Skip 1, Keep both 1”).
   - The Connect dialog and the connection questions (milestone 6, #286): the Connect dialog starts on its Address field; each field is a labelled input whose hint and problem are its description (`aria-describedby`), a refused field is `aria-invalid` with its message in a `role=alert` under it, and the sign-in methods are a `fieldset` of radio buttons with a legend. The outcome of Test, Save, Duplicate and Delete is written in a `role=status` line in the dialog and announced through the window's polite live region; a dropped password is said in the address field's hint. The saved connections are a list of buttons named “Edit {name}”, with Duplicate and Delete buttons named after the connection; the current one has `aria-current`. Deleting asks in a dialog that starts on Cancel. The questions are dialogs of their own stacked over it: Sign in starts on its first field and Enter signs in; Trust {host}? and the certificate dialog start on Cancel; the changed-key warning starts on Cancel, says why in a `role=alert` paragraph read when it opens, shows both fingerprints as a description list, and its only way to connect is the danger-styled Trust the New Key button. Nothing is shown by colour alone: a failed test says “Not connected:” and why.
   - The Network section and remote states (milestone 6, #287): the section is a labelled group whose list uses the sidebar's list keyboard pattern (Up, Down, Home and End; each row a tab stop), each row's accessible name holds the server's name and its state in words, so the state dot is never the only sign, and the server the active tab is on has `aria-current="location"`. A change of state is announced in the sidebar's polite live region (“NAS: Connected”). The row's menu opens with the Menu key or Shift+F10, and Delete… asks in a dialog that starts on Cancel. A server tab's description says “On a server:” and its state. A folder that cannot be shown for its connection is a `role=alert` with a heading, the reason in words and one action button; while it connects it is a `role=status` saying “Connecting to {server}…” with a spinner that stops under reduced motion. The path bar's note about a dropped password is a `role=status` tied to the field.
   - Archives (milestone 6, #297 and #298 as built in the app): the compress dialog is the shared `Dialog` that starts on its Archive name field (selected, so typing replaces it), each field labelled, a refused name `aria-invalid` with its reason in a `role=alert` line that is read out, Enter compresses and Esc cancels; changing the format changes only the end of the name, so the name and format never disagree. A locked archive is a `role=alert` state with a heading naming the archive and one button, Enter password, which asks in the same sign-in dialog a login uses (starting on its password field, with no Remember choice because the password is never saved); a password that could not be given is stated under the button and announced. A listing that has to read a whole compressed tar replaces the plain opening message with a `role=status` line that says why it takes a while and is announced. Extract and Compress are commands with the usual names in the menus, the palette and the Action bar (Extract all is a button with its label and tooltip, left out outside an archive), run from the keyboard like the others, and tell how it went in the status line (entries left out, a password the archive refused) and the job's own announcements.
4. **Drag and drop.** Provide a non-pointer path for every drop: Copy To… and Move To… cover files; the tab menu covers splitting. Announce drop targets and results in the live region.
   - File drags (milestone 4, slice 12): every outcome has a path without a pointer, listed in `NON_POINTER_PATHS` (`dnd/fileDragModel.ts`) and checked by `fileDragParity.test.tsx`: Copy To…, Move To…, Link To… (in the Edit menu and the palette, with no key), Move to Trash (Delete), Open in New Tab, Paste Into Folder and F5 for a folder, a pane and the other pane, and the destination dialog for a place, a tab or a breadcrumb. The drag says "Dragging 3 items" when it starts, "Over Documents: will move" (or why it is not allowed) as the target changes, "Opened docs" and "Returned to where the drag began" for a spring, "Drag cancelled" on Esc, and the result comes from the queue (the toast and its Undo). The ghost and pill are `aria-hidden` because the live region says the same words. The action picker is the shared context menu named "Drop action" (arrows, Enter, Esc), and closing it without a choice says "Drop cancelled". A refusal is shown by words and a dashed edge as well as colour, and under Reduce motion the shake and the spring ring's animation are off.Files dragged in from other applications use the same words ("Dragging 3 items", "Over Documents: will copy", "The files left the window"), a drag that continues as the system's says "Dragging notes.txt out of the window" and its end is read out ("Dropped…", "Moved … to another application", "Drag cancelled"), and a refusal to start it is a notice. These drags have no keyboard path of their own: Copy, Cut and Paste with the system clipboard do the same (`NATIVE_DROP_PATHS`, `OUTBOUND_PATHS`).
5. **Progress.** Done for the queue (milestone 4, slice 06): the status bar ring is a button named by its state ("Operations, 2 in progress, 50% complete, waiting for you"), with `aria-expanded` and `aria-haspopup="dialog"`, and colour is never the only signal (the count, the label and a dot with the state in the name). The popover is a non-modal `role=dialog` named "Operations": it opens with Enter or Space, puts focus on the first job row (or on the panel when the list is empty), closes with Escape and returns focus to the ring, and closes without taking focus when a press or Tab lands outside. The rows are a list with one tab stop (Up, Down, Home and End move between rows; Alt+Up and Alt+Down reorder a queued job and announce the new position); each row is named by its title and described by its state, and its buttons are named "Action: title". The live region speaks a job starting (once), waiting for the person, failing, being cancelled and finishing, with how many others are still in progress, and 25, 50 and 75 % of a job that has run three seconds, never every tick. The ring does not animate (a job not yet sized is a still quarter, not a spinner) and its fill transition is off under reduced motion. Still to do: a screen reader pass, and the Operations window's own focus order.
   - Inline rename (milestone 4, slice 07): the field is named "Rename name" and described by a hint ("Enter renames, Escape cancels.") and by a polite live region under it that holds what is wrong with the name or why Rust refused it, so a taken name is read out as it appears; `aria-invalid` follows. The extension question is the shared `Dialog` with "Keep .jpg" focused and Escape returning to the field. When the field ends, focus returns to the file list (whose active descendant is the renamed row), and a finished rename is announced ("Renamed a.txt to b.txt"). A new folder or file opens in the field with its default name selected, so the result of F7 is spoken as the field's name. Delete Permanently's confirmation lists the items and starts on Cancel; refusals (read-only location, nothing selected, nothing to undo, an undo that cannot be done and why) are said through the toast's live region, never dropped.
   - The Shelf (milestone 4, slice 14): dropping on the Shelf is reached without a pointer by Add to Shelf in the file menu, the Edit menu and the palette (`NON_POINTER_PATHS.shelf`), and dragging out by Copy and Paste or Copy To… on the item (Ctrl+C in the panel puts the files on the clipboard). The panel is a landmark named "Shelf" holding a tree (`aria-multiselectable`, groups at level 1 and items at level 2, `aria-activedescendant` for the row the keyboard is on) with Up, Down, Home, End, Left, Right, Enter, Space, Ctrl+A, Esc, Delete, Ctrl+C and the Menu key; its edge is a separator with `aria-valuenow` that the arrow keys move. Removal is announced ("Removed 2 items from the Shelf"), added items are said in the status toast, a full Shelf says so, and "Missing" is a word beside a dashed border, not only a dimmed row. The drag pill reads "Add 3 items to the Shelf" in the live region and refusals give their reason as for any drag.
   - Settings window (milestone 4, slice 18): the pages are the shared `SettingsShell` (a `nav` of section buttons with `aria-current` and a roving tab stop, a `main` named by its heading, groups named by their titles). Every row's control is named by its label and described by its description; a toggle is a `switch`, a choice of two or three is a `radiogroup`, and a number field has its unit beside it. A change applies at once, so there is no Save button to find; a refusal appears under its row as an `alert`, the field is marked `aria-invalid`, and it keeps the value that is in force. A row that depends on another is disabled and says what to turn on in its description (the word "Unavailable" is kept for what a system cannot do, such as dragging files out to other applications, which the Drag & drop page explains in text). `Ctrl+,` opens the window from any main window. The Experimental page (D167) follows the same pattern: each remote protocol is a `switch` whose name is its label and its Experimental badge together ("SFTP Experimental"), described by its one line; a protocol the build does not include is a disabled switch that says why, and a link from another window (an address of a protocol that is off) opens the window on this page. A location of a protocol that is off is an `alert` with a real button that opens the page, in a tab, in the path bar and in the Connect dialog; a dimmed Network row keeps its reason as text under its name, so colour and dimming are never the only sign.
6. **Focus order.** Title bar, tab strip, toolbar, action bar, sidebar, files, inspector, status bar. Confirm with a keyboard-only pass.
7. **Colour is never the only signal.** Git status has letters; tags need names in the row tooltip; connection dots need text alternatives.
8. **Icon-only buttons** (view switcher, joint, action bar in narrow windows) need accessible names. Most have a title; add aria-labels.
9. **Pointer-only gestures** (long-press history, hold-to-split) need keyboard equivalents. Alt+Left/Right with a menu key, and Split With in the tab menu, cover them.
10. **Minimum sizes:** text stays at or above 12 px; touch mode covers 44 px targets.
