# Waypoint — Product & Design Spec

Status: draft v0.1 · 2026-09-29 · Owner: Liminal HQ
Related: `docs/*` (goals, decisions, interactions, plugins, theming, shared components, prototype plan, open questions)

---

## 1. Summary

Waypoint is a tabbed Linux file manager for local files, remote servers and virtual locations (archives, git repos, cloud drives). It's built to be extended with plugins. It takes Nemo's calm, capable desktop feel and adds:

- **Tabs as first-class objects:** tear off, merge, pin, group or colour them, and split any one of them.
- **Super drag and drop:** a persistent Shelf, spring-loaded folders and tabs, drops onto remotes, a modifier action picker, and drags out to the terminal and other apps.
- **Every location is the same:** SFTP, SMB, WebDAV, S3, Git, archives and cloud drives all browse like local folders.
- **Plugins:** they add columns, actions, location providers, thumbnailers, previewers and panels.
- **Designed for the desktop it runs on:** light and dark modes, OS accent and icon theme, native-feeling frames on GNOME, Cinnamon, KDE and Windows 11, and optional window transparency.
- **Family fit:** the shared Liminal HQ title bar and context menu, the same type and tokens, and the same settings patterns as Emoji Nook, Jar and Threshold.

Assumed stack, matching the family: Tauri v2, React and Rust. The spec is written for UI and UX. Engineering notes are marked **[eng]**.

## 2. Users & jobs

| Persona            | Top jobs                                                                                   |
| ------------------ | ------------------------------------------------------------------------------------------ |
| Desktop generalist | Find, open and tidy files; move photos off a phone; empty the trash                        |
| Developer          | Jump between repos, see git status, open a terminal in the current folder, SFTP to servers |
| Homelab / sysadmin | Manage SMB shares, S3 buckets and remote logs; do bulk ops with verification               |
| Creative           | Browse by thumbnail, batch rename, convert and resize images, tag work                     |
| Power user         | Keyboard-only use, Vim nav, command palette, custom plugins                                |

## 3. Scope

### In scope (v1 design)

1. Main browser: tabs, sidebar, path bar, toolbar, views, split pane, status bar
2. Remote connect and browse
3. Drag and drop system, including the Shelf
4. Command palette (Ctrl+Shift+P)
5. File operations queue, conflict resolver and verification
6. Properties, preview and Quick Look
7. Plugin manager
8. Settings, including Appearance and Transparency
9. Developer options
10. Supporting features: tags, smart folders, terminal drawer, disk usage, trash, bookmarks and workspaces, session restore, devices and encrypted volumes, Flow integration, batch rename

### Non-goals (v1)

- Desktop icon management and wallpaper
- A built-in text or code editor (Waypoint only previews)
- Sync engines (cloud plugins mount; they don't sync offline)
- Anything AI-driven (rename rules are deterministic)

## 4. Information architecture

```
Window
├─ Title bar (shared Liminal component; app menu, title, window controls)
│   (the app menu button shows the Waypoint logo and name; Settings → General → Title bar starts the title's label with “Waypoint”, off by default)
├─ Menu bar (optional, own row; Settings → General → Title bar → “Show a menu bar under the title bar”, off by default)
├─ Tab strip (own row, below the title bar)
├─ Toolbar row: back/forward/up · path bar · search · view switcher · panel toggles
├─ Body
│  ├─ Sidebar (collapsible): Favourites · Workspaces · Places · Devices · Network/Remotes · Smart folders · Tags · Plugins
│  ├─ Pane A │ Pane B (optional split, per tab)
│  ├─ Shelf (docked along the bottom of the content column, under the panes and beside the sidebar, or undocked into its own window; holds dragged items across tabs and windows)
│  └─ Inspector (optional): Preview · Properties · Git (in a working tree) · Plugin panels
├─ Terminal drawer (optional, bottom, follows the active pane's cwd)
└─ Status bar: selection summary · free space · ops queue indicator · plugin status items
```

Overlays: command palette, Quick Look, ops queue popover, conflict resolver, connect dialog, batch rename, context menus, Settings window, Plugin manager, Developer options.

## 5. Core surfaces

### 5.1 Title bar

- Uses the **unified Liminal title bar** (see `docs/shared-components.md`). Tabs are **not** in it; they get their own row.
- Contents: app mark and menu button (left), window title with the current location (centre), Always on Top, Minimise, Maximise/Restore and Close (right).
- **Application menu** (the app-name button, upper left, after any window buttons the desktop keeps on that side): **File** (New Window, New Tab, Connect to Server… where server connections are available, New Folder, New File, Rename, Batch Rename…, Duplicate, Move to Trash, Delete Permanently, Settings…, Close Tab, Reopen Closed Tab, Close Window), **Edit** (Undo and Redo named from the history, Undo History ▸, Cut, Copy, Paste, Copy To…, Move To…, Link To…, Select All, Invert Selection), **View** (List, Grid, Show Hidden Files, Sidebar, Action Bar, Split View, Command Palette…) and **Window** (Duplicate Tab, Move to New Window, Always on Top where the window manager can do it) and **Help** (Help, Keyboard Shortcuts, Take the Tour, About Waypoint). Each row shows its key; a command that cannot work here is hidden (the write commands in the Trash or a read-only folder), and one that needs something first is disabled with the reason as its tooltip. **View** also lists the Inspector (F11). **Undo History** lists the history's entries newest first with the time of each (an undone one says so); only the entry Undo would undo and the entry Redo would redo can be chosen from it, and the older ones are shown disabled because a later change may depend on them; its last row, More in Command Palette…, opens the palette on “undo”, which offers every entry. F10 or a lone Alt opens the menu (and closes it again when it is open, returning focus to where it was), and Alt+F, Alt+E, Alt+V, Alt+W and Alt+H open File, Edit, View, Window and Help. It is the same list of commands the keys and the Action bar use. The window menu on empty bar space is separate.
- **Command palette** (Ctrl+Shift+P from anywhere in a main window, including a text field; also View → Command Palette…): a modal panel near the top of the window with a field and a list of the window's commands, the same ones the menus, the keys and the Action bar run. Typing filters by a case-insensitive match of the letters in order (“nf” finds New Folder), best match first; matched letters are bold. Ties go to a command run recently, then File, Edit, View, Go, Tabs, Window and App order. With nothing typed the last five commands run in this window come first, then the rest. Each row shows its group as a muted hint and its key on the right. A command that cannot work here is hidden; one that needs something first stays, greyed with the reason beneath it, and Enter or a click on it says the reason and does nothing. Go to Home, Desktop, Documents, Downloads, Pictures, Music, Videos and Trash open those places, and Link To… makes links on the computer's own folders (not offered on Windows, where making a link needs a privilege). **Undo history:** typing brings in a row for each older history entry (“Undo 3 changes back to: Move 3 items to Trash”, with when it happened: “2 minutes ago”, or the date and time in the system's 12 or 24-hour clock after a week). Choosing an older entry undoes it and every change newer than it, newest first, each as its own job; a redo row does the mirror, oldest first. More than one change, or an undo that had stopped part way, asks first, listing what goes, with Cancel focused. It stops at the first change that cannot be undone and says how many were undone and why it stopped (“Undid 1 of 3 changes. Stopped at New folder: it has been changed since”). The arrow keys, Home, End, PageUp and PageDown move through the list while typing stays in the field; Enter runs the row, and Esc, a click outside or leaving the window closes it with focus returned to where it was.
- **Menu bar (optional):** Settings → General → Title bar → “Show a menu bar under the title bar” (off by default, saved in the `ui` settings and applied live in every Main window) puts the application menu's menus (File, Edit, View and Window) in a row of their own between the title bar and the tab strip. They open exactly as the app menu's submenus do: the same rows, commands, state and keys. While the bar is shown, the title bar's app mark and name stay but are plain text that opens nothing, and the bar takes F10, a lone Alt and Alt+F, E, V and W. Alt plus a letter opens that menu; F10 or a lone Alt moves focus to the bar's first menu, and pressing it again, or Escape, returns focus to where it was (with a menu open it closes the menu instead). Left and Right move between menus, Home and End jump, Down, Enter or Space opens one, and while one is open Left and Right switch to the neighbouring menu and hovering another opens it. Menus that do not fit collapse, last first, into a More menu. Settings, the Shelf and the other windows have no bar.
- Double-click toggles maximise. The whole bar is a drag region except its controls.
- On Windows 11 the controls follow the Win11 order and style (see §9). GNOME and KDE button layouts follow the OS setting.

### 5.2 Tab strip

- Each tab shows an icon (folder, remote badge or plugin icon), a truncated title, a close button on hover, and an optional colour dot or group chip.
- **Pinned tabs:** icon only with a small pin mark, grouped on the left and kept in view when the strip scrolls. A pinned tab has no close button and a middle-click does not close it; Ctrl+W, Delete and the tab menu's Close Tab still do. A tab cannot be dragged or moved across the pinned boundary. Close Other Tabs and Close Tabs to the Right leave pinned tabs open (the pinned tabs are never counted as “others”, and a tab's pair partner is another tab, so it closes too unless it is pinned); each announces what it did through the live region, and the tabs it closes go to Recently Closed.
- **Colours:** a tab can carry one of nine colours (red, orange, yellow, green, teal, blue, purple, pink, grey), shown as an accent along its top edge. The colour's name is in the tab's tooltip and accessible description, so it is never conveyed by colour alone.
- **Tab menu** (right-click, or the Menu key or Shift+F10 on a focused tab): Pin Tab or Unpin Tab, Colour ▸ (None and the palette), Duplicate Tab (the same location beside the tab, without its history), Move to New Window, Move to Window ▸, Close Tab, Close Other Tabs, Close Tabs to the Right, Reopen Closed Tab and Recently Closed ▸. Add to Group ▸ (the window's other groups, then New Group) and, for a grouped tab, Remove from Group; a grouped tab's Pin item reads “Pin Group “name”” because pinning a grouped tab pins its whole group. Split With ▸ (the tabs that are not already paired) on a single tab, or Separate Tabs, Swap Panes, Layout ▸, Reset Sizes and Close Both on either half of a pair.
- **Groups:** a named, coloured chip that collapses its tabs. Drag a tab onto a chip to join the group, drag a tab out past the group to leave it, and drag the chip to move the whole group.
- **Split indicator:** a pair's tabs sit together as one bridged pill with a small split glyph (the joint) on the seam. Each half is still a tab with its own focus stop, and a click on a half activates that pane; the pill's accessible name is “Split: A and B”, and it shares pin and colour. The joint's right-click menu (Menu key or Shift+F10 when it has focus; the same actions are on either half's tab menu) has Separate, Swap Panes, Layout ▸ (Side by Side, Stacked), Reset Sizes, Pin or Unpin, Colour ▸, Duplicate Split, Move to New Window, Move to Window ▸ and Close Both. A plain click does nothing and a double-click resets the pane sizes.
- **Tear off:** drag a tab out of the strip to spawn a new window under the cursor. Where the system allows it a ghost follows the pointer, even outside the app. On a Wayland compositor that supports `xdg-toplevel-drag` (GNOME's Mutter does) the new window itself follows the pointer and stays where it is let go; on any other Wayland compositor the compositor places the window. Native pattern in `docs/tauri-tear-off.md`.
- **Merge:** drop a tab onto another window's strip, or onto a tab's body to put it next to that tab (SPEC §13c). On Wayland, where the compositor supports `xdg-toplevel-drag`, dropping the dragged window on another window's strip merges it at the slot shown there, and on its body at the end of its strip; otherwise Move to Window ▸ does it.
- **Spring-load:** while you hover a file drag over a tab for 600 ms, that tab activates.
- Middle-click a folder to open it in a new tab beside the current one, without leaving the current tab. **Ctrl+middle-click** opens it in a new window, on a folder in the file view and on a place, favourite or tree folder in the sidebar; their menus have Open in New Window too. Middle-click a tab to close it.
- **New window:** Ctrl+Shift+N opens a window with one tab at Home. It opens the size of the window it came from, 30 px down and to the right of it on the same monitor on X11 and Windows (back at the monitor's corner when that would run off the screen); on Wayland the compositor places it. A notice warns from the eighth open window (“Many windows are open…”), and a thirteenth is refused with a notice (moving every tab of a window to a new window is not a thirteenth, because the window it leaves closes).
- **Move a tab to another window:** the tab's menu (right-click, the Menu key or Shift+F10) has **Move to New Window** and **Move to Window ▸**, which lists the other windows by their active folder and tab count (“Documents — 3 tabs”). The tab keeps its history, pin, colour and id; its scroll position and focused entry are sent just before the move and restored in the window that receives it. The window that receives it comes to the front, says “Moved Documents to this window”, and the window it left says “Moved to a new window” or “Moved Documents to Downloads”. Moving a window's last tab closes that window; a moved tab is not a closed tab and does not appear in Recently Closed.
- **Keyboard:** the strip is a tablist with roving focus. Left and Right move focus along the tabs (Home and End jump), Enter or Space activates the focused tab, Ctrl+Shift+Left or Right moves it, and Delete closes it. Ctrl+T opens a tab at the current folder, Ctrl+W closes the active tab, Ctrl+Shift+T reopens the last closed tab, Ctrl+Tab and Ctrl+Shift+Tab step through the tabs in most-recently-used order, committed when Ctrl is released (a small list of the tabs shows the candidate while Ctrl is held, Escape cancels, and the candidate is announced to screen readers), and Alt+1 to Alt+9 go to that tab. Dragging a tab along the strip reorders it, and Escape abandons the drag; the other drag outcomes (SPEC §13c) all have a menu route: Split With ▸, Add to Group ▸ (including New Group), Remove from Group and Move to New Window.
- **Last tab and last window:** closing the last tab of a window closes the window, and closing the last window quits Waypoint. Closed tabs, including the tabs of a closed window, go to Recently Closed (the last 10, kept with the session).
- Each tab keeps its selection and scroll position while it is open; a background tab gives up its cached rows after a short while and refreshes them when you return.

#### The + button

- **Click:** new tab in the current folder. **Middle-click:** new tab at Home. **Right-click, or press and hold for about half a second,** opens a menu (the Menu key or Shift+F10 does too, when the button has focus). Milestone 3 has New Tab, New Tab at Home, New Window (announced as “Opened a new window”), Reopen Closed Tab and Recently Closed ▸, and milestone 6 adds Connect to Server… where server connections are available; the full list is: New Tab, New Tab at Home, New Empty Tab (start page), New Tab in Group, New Split Tab, New Tab from Clipboard Path, New Window, New Terminal Tab, Connect to Server, Reopen Closed Tab, Recently Closed Tabs (last 10), Open Bookmarks. The closed list is read afresh each time a menu opens.
- **Drop:** on the button or on the strip's empty space (not a tab, a group chip or a scroll arrow), a folder opens a new tab there; a file opens its parent folder; several folders open several tabs; holding Alt opens a split pair.
- **Double-click the strip's empty space:** a new tab in the current folder at the end of the strip, as in a browser. A double-click on a tab, a group chip, a pair or a button does nothing extra.
- The button is fixed at the right end of the strip, next to the all-tabs list. Tabs scroll horizontally when they overflow, with arrows that appear only when needed.

#### Start page (New Tab)

- A tab whose location is the start page. Choosing a destination opens it **in the same tab**, which then becomes a normal folder tab. Its tab reads “New Tab” with a plus icon.
- **Layout:** card grid under a search box. Sections: Quick Actions, Pinned, Bookmarks, Recent Folders, Recent Files, Servers, Devices, Tags, Recently Closed.
- **Cards:** a folder-peek thumbnail, a live count or status (items, connected, free space), and a hover row with Open in new tab and Remove. Cards in Pinned, Bookmarks and Recent Folders can be dragged to reorder.
- **Sections:** collapsible (remembered). Customise mode adds a drag handle and an eye toggle to each section header, to reorder or hide it.
- **Drop:** dropping a folder on Pinned, Bookmarks or Recent Folders adds it.
- **Ways to open one alongside other tabs:** right-click the + button → New Empty Tab, Ctrl+Alt+N, the app menu, the tab's right-click menu, or the command palette (“New empty tab”).
- **Automatic use:** optionally shown when the last tab is closed (Settings → Tabs & Windows), or as a startup tab.
- **Not Overview:** the Start page is the launcher a new tab shows. Overview (§5.8a) is a place you go to for volumes, the Trash and where the space went; it is a location (`overview:/`) that opens as the tab's content, and the Start page's Devices cards link to it.

#### Terminal tab

- **New Terminal Tab** creates a real tab that joins the current tab as a pair, beside it. It stays in the folder where it started; `cd` inside it does not move the other pane.
- The tab shows a terminal icon and a title that follows the shell (the folder, or the running command while one is busy). Double-click to rename. Long titles truncate in the tab, and the full title shows in the tooltip and the pair header.
- Dropping files inserts their quoted paths; Alt-drop changes directory.

#### Startup

Settings → General → When Waypoint starts: **Restore last session** (default) or **Open startup tabs**, a list where each tab is the start page, Home, a folder you choose (path field with autocomplete and Browse), or the current workspace's folder. “Apply now” previews the choice in the open window.

#### Tab groups

- A group is a coloured label in the tab strip followed by its tabs. Groups belong to one window.
- **Size:** no hard limit. Past 8 tabs the label gets an amber outline, shows the count, and adding a tab shows a warning suggesting a split.
- **Pairs:** a joined pair (split view) always stays together inside a group. Adding, removing, pinning or colouring one half applies to both.
- **Label:** click collapses or expands (a collapsed label reads “Site · 3”). Double-click renames in place. A new group is auto-named “Group N” and enters rename immediately.
- **Right-click menu:** Rename Group, Change Colour, Collapse or Expand, Collapse All Other Groups, New Tab in Group, Pin or Unpin Group, Sort Tabs in Group (by name, by location, local first), Duplicate Group, Save Group as Workspace, Move Group to New Window, Move Group to Window ▸ (the other windows, as for a tab; the group keeps its name, colour and collapsed state), Ungroup, Close Group (closing every tab of a window this way closes the window, as closing the last tab does, and the tabs go to Recently Closed).
- **Collapsed groups and the active tab:** a collapsed group hides its tabs, and the chip stands in for them. When a hidden tab becomes active by any other route (Ctrl+Tab, Alt+digit, reopening, a neighbour closing) its group expands, since an active tab nobody can see is worse than an open group. Collapsing the group that holds the active tab is allowed: the tab stays active, the chip says it contains the active tab, and it becomes the strip's tab stop.
- **Soft limit:** past 8 tabs the chip's amber outline and count appear. When a tab joins a group that is over the limit, Waypoint says so in a short note under the strip and through the live region, and never refuses the tab.
- **Without a pointer:** every gesture has a menu or key path (drag, SPEC §13c, is only a shortcut). Left and Right reach a chip like a tab; Enter or Space on it collapses or expands, F2 renames, the Menu key or Shift+F10 opens its menu, and Ctrl+Shift+Left or Right moves the whole group. Ctrl+Shift+Left or Right on a tab inside a group keeps it inside; leaving a group is Remove from Group. Save Group as Workspace names the workspace after the group and, when that name is taken, asks for another in a name field on the chip, and Move Group to New Window says so, without failing, when the window cannot be made.
- **Screen readers:** the chip is a button named “Site, tab group, 3 tabs” that reports `aria-expanded`; it is in the tablist's roving order but is not itself a tab. Its tabs stay `tab`s, and each one's description starts “Group: Site”. Creating, renaming, collapsing, colouring, adding, removing, ungrouping and closing a group are announced with the group's name and its tab count.
- **Drag and drop:** drag the label to move the whole group; drag a tab onto a label to add it; drag a tab out of the group's span to remove it; drag the label out of the window to tear the group off; drag a folder onto a label to open it as a new tab in that group.
- **Workspaces:** saving a group as a workspace adds its folders, in tab order and each once, as a named set in the sidebar's Workspaces section, and says so (“Saved workspace Site”); it does not switch the Favourites. Workspace names are unique, ignoring case.
- Overflow: the strip scrolls and a tab list menu appears. Ctrl+Tab cycles tabs in most-recently-used order, committed when Ctrl is released.

### 5.3a Search

Clicking or focusing the search box (or pressing / or Ctrl+F) opens a search bar under the toolbar. Its chips set the **scope** (this folder, with subfolders, Home, the current workspace, open tabs, or a chosen place) and **filters** (type, date, size, tags, permissions), plus toggles for searching inside files, hidden files, match case and regular expressions. Results replace the folder view, with a Location column, highlighted matches in names and a snippet for content matches, live progress with a Stop button, and an optional grouping by folder. From the bar: save as a smart folder (appears in the sidebar), open in a new tab, or close (Esc). Right-click a result → Open Containing Folder.

### 5.3 Toolbar & path bar

- Back, forward and up, each with a long-press history menu. Up is disabled where the location has no parent. **Alt+Left, Alt+Right and Alt+Up** do the same from the keyboard.
- **Path bar:** breadcrumbs by default, each one navigates. A middle-click on one opens that location in a background tab (Ctrl+middle-click in a new window). Click empty space or press Ctrl+L to edit it as text with autocomplete (local paths, `sftp://`, bookmarks, recent). Enter goes, Escape (or clicking away) cancels, and text that is not a location shows a message under the field and keeps it open. Typed text is parsed by Rust (`~`, relative paths and `file://` are understood, and the server schemes of §7 that a provider serves and the person has turned on in Settings → Experimental, `sftp://`, `smb://`, `davs://` and `dav://` in this build; one that is off says so and links to the page, D167), never split or joined in the UI; a password typed in a server address is stripped and never shown, and the bar says so before going (D147). Autocomplete and sibling dropdowns on the breadcrumbs come later. Breadcrumb segments are drop targets and have sibling dropdowns.
- Search: filter-as-you-type in the current folder, with Enter for recursive search and saved-search chips.
- The view switcher is not in the toolbar: per D23 the view icons live in the status bar footer (§5.8), and sort and group live in the empty-space context menu (§5.5).
- **Panel toggles** at the right end of the row, after the path bar: Sidebar (F9) and Split View (F3), each a toggle button pressed while its panel shows, with a tooltip of its name and key. A press runs the same command as the menu, the palette and the key. The Shelf is not here: it has its button in the status bar (§5.8). The inspector and terminal drawer toggles join them when those panels exist. When the toolbar is narrow the toggles collapse into one More menu that lists the same commands with their state.

### 5.3b Navigation and selection

- **History menus:** right-click, long-press or press the menu key on Back and Forward to see the folders behind and ahead (nearest first), and jump to any of them. The history belongs to the tab and is kept by the session.
- **Go to…** (Ctrl+Shift+G): type a location, with recent, saved and matching folders below. Until those lists exist it opens the path bar's text editor, the same as Ctrl+L. A missing, unreadable or not-a-folder location shows its own error state, not a blank view, and leaves the tab's history intact so Back returns to where you were.
- **Copy To… / Move To…:** in the item menu (and the file menu); a dialog asks for the destination. A path field has the focus: type a path (`~`, relative to the pane's folder, or `file://`, parsed by Rust) and a line under it says in words whether the folder can be used (it exists, is a folder, can be written to), or choose one below from Places, Favourites, Open tabs and Recent folders (the last few chosen here). Copy To… starts with the last destination in the field; Move To… starts with it empty, so Enter never moves the selection to a folder that was not named this time. Enter chooses the folder once it checks out, Esc cancels, and Copy or Move waits for a usable folder. **New Folder…** makes a folder in the folder shown in the field, through the queue, and chooses it. A move into the folder the items are already in is refused in the dialog; a copy into it makes copies beside the originals (“name (2)”). Drives and servers join the lists with the locations that provide them. Conflicts and failures are the queue's (§8).
- **Open With…:** the item menu has an _Open With_ submenu: the default application (named, with its icon), the applications registered for the file’s type, and _Other Application…_. On Linux _Other Application…_ opens an in-app chooser that lists the other installed applications and filters as you type (Enter opens the first match); on Windows, and in a Flatpak sandbox, a single file goes to the system’s own chooser instead. _Open With…_ in the File menu and the command palette opens the same chooser listing every application, for the selection of the active pane. It applies to local files (up to 50 at once) of one type: a selection of mixed types, or a system where the mime-apps plugin reports nothing that works (the Services panel says why), shows no Open With at all. The “always use for .ext” option arrives with the Inspector’s default-application control; the Inspector already names the default application on its Properties tab.
- **Select tools:** Select by Pattern (Ctrl+S, with * and ? wildcards, select/add/deselect and a live match count), Invert Selection (Ctrl+I), Select Similar, Deselect All.
- **Per-folder view:** a folder remembers the view (List or Grid), sort, grouping, hidden-files choice and grid icon size chosen in it, and shows them each time it opens, in any tab or window. Only what was chosen is remembered: sorting a folder does not fix its view, and a folder nobody has changed shows the window's own sort and grouping, hidden-files choice and icon size, and the view the window started in. The choices are made where they always were (the View switcher and the icon size slider, Ctrl+1, Ctrl+2 and Ctrl+H, the column headers, the empty-space menu, the Sort and Group commands) and are kept at once (a run of slider steps is kept once it settles), so a change in one window appears in the folders open in the others. The Trash and Overview have their own and remember nothing. **Waypoint remembers at most 1,000 folders; once there are more, the one whose view was changed longest ago is forgotten** (only changing a view counts, opening a folder does not). _Reset This Folder’s View_ (View menu, the command palette and the empty-space menu; listed disabled for a folder that remembers nothing) makes the folder forget all of these, so it shows the window's again. Turn it off in Settings → General → _Remember each folder’s view_ (on by default; its description states the 1,000-folder limit): every folder then shows the window's view, as before, and what folders remembered is kept for when it is turned on again. The remembered views are saved with Export settings.
- **Columns:** right-click the list header (or focus a heading and press the menu key or Shift+F10) to show or hide Git, Media, Kind, Modified, Permissions, Owner and Created. _Built so far:_ the **Git** column, offered only in a folder of a Git working tree and shown by default (the choice is kept in the `ui` settings and applies at once in every window); the other columns arrive with their features.
- **Git status (milestone 6):** in a folder inside a Git working tree, Waypoint reads the repository (never changing it, and without ever running the `git` program) and shows what Git says, kept current within a second of a change on disk. The list gains a **Git** column beside Name with two letters, the change staged for the next commit and the change not staged (`M` modified, `A` added, `D` deleted, `R` renamed, `T` type changed, `?` untracked, `!` ignored, `U` conflict), and a dot for a folder with changes inside it; the same letters sit in a small chip at the corner of an item in the grid. Colour only repeats them: every mark has the same thing in words (_Modified, staged; Modified, not staged_, _3 changed items inside_) for a screen reader and a tooltip. Ignored items are dimmed and a clean one has no mark. Pressing the column heading (or _Sort by → Git status_, in the empty-space menu, the Action bar's Sort menu and the command palette) sorts conflicts first, then edits, additions, new files, clean items and ignored ones last. A folder that is itself a repository carries the Git sticker in the Portage icon set. The status bar shows the **branch** (or the abbreviated commit of a detached head), `↑2 ↓1` for the commits ahead of and behind its upstream, a dot when anything is changed and the operation in progress (a merge, rebase, cherry-pick, revert or bisect), with the whole state as a tooltip and in words for assistive technology (the item is not a live region, so a change of branch is not announced). Favourites and places that are in a working tree with changes show a dot in the sidebar, with the count in words. Without a repository there is nothing: no column, no item, no menu entry. Settings → General → _Show Git status_ (on by default) turns all of it off, and then Waypoint reads nothing from repositories; the Services panel lists **Git status** and says when it is off or has to poll because the system cannot watch the folders. A `git+file:///repo!/inner?rev=main` location (§7) browses one revision read-only, and Up from the top of a revision goes to the repository's own folder. Staging and committing are the Git extension's (milestone 8).
- **Errors:** permission denied (with _Open as Administrator_, an authentication prompt), not enough space (with _Choose Another Location_), invalid names (with the reason, for example FAT drives), name already in use, and failed jobs (Retry and Dismiss in Operations).

### 5.4 Sidebar

Sections can be reordered and collapsed:

- **Favourites:** pinned folders.
- **Workspaces:** named bookmark sets that switch the Favourites list.
- **Places:** Home, Desktop, Documents, Downloads, Pictures, Music, Videos, Trash. Trash opens `trash:/` in the tab and shows a live badge with the number of items in it. Where the Trash cannot be browsed (the Flatpak portal can only trash) the place stays and shows an explanatory "Trash can't be browsed here" state with the reason, instead of a list.
- **Devices:** drives with usage bars; Mount, Unmount and Eject are separate actions, and a busy device says what holds it. Locked encrypted volumes show a lock and unlock inline; with _Remember encrypted-volume passphrases_ turned on in Settings → Integrations (off by default, D153) the Unlock dialog offers _Remember in keyring_, and a remembered volume unlocks and mounts by itself when it is plugged in. Changes appear within a second of plugging in. Overview (§5.8a) shows the same volumes in full.
- **Network:** saved remotes, each with a connection status (connected, connecting, disconnected, or a problem with its reason), written in words as well as shown by a dot. A remote opens in the active tab; its menu has Connect or Disconnect, Edit Connection and Remove. The list is Rust's (saved connections never hold a password, D147), shared by every window. As built (#287, D160): the section sits between Devices and Favourites in every Main window that can connect to servers. Saved connections come first, in their saved order, then **Recent servers** (connected to without being saved). Each row has the server glyph with a state dot and, written under the name, its state: Not connected, Connecting…, Connected, Offline, Sign-in needed, Key to review or Error, with the reason (“Offline · Not connected: the server refused the connection.”); each change is announced politely (“NAS: Connected”). A click opens the server in the active tab (connecting it, D146), a middle-click in a new tab, and the server the active tab is on is marked as current. A connected server has a **Disconnect** button. The row's menu (right-click, the Menu key or Shift+F10) has Open, Open in New Tab, Connect or Disconnect, then for a saved connection Edit… (the Connect dialog), Move Up, Move Down and Delete… (asking first, starting on Cancel, and offering to forget the saved password), and for a recent server Save… (the Connect dialog with its address filled in) and Forget. **Connect to Server…** ends the section. Dropping onto a server comes with transfers (#305).
- **Smart folders:** saved searches.
- **Tags:** colour labels.
- **Plugin sections:** added by plugins.

**Folders section:** an expandable tree that follows the current folder, loads children when opened, lists hidden folders when hidden files are on, and shows servers and archives as branches. Folders are drop targets that spring open. The _Places / Folders_ switch at the top turns the tree into the whole sidebar. **Editing:** right-click Places, Favourites and servers to rename, reorder (or drag), remove, add the current folder (Ctrl+D) or edit a connection; dropping a folder on the Places or Favourites heading adds it. A **Recent** section lists the last eight locations.

Every item is a drop target. Hovering an item during a drag springs it open after 600 ms.

**What milestone 2 ships of the sidebar:** a collapsible left panel (toggle button in the toolbar, **F9**) with the **Places / Folders** switch at its top, showing either **Places** with **Favourites** and **Workspaces** (added in milestone 3), or the **Folders** tree on its own; the other sections, drag and drop into the sidebar and the Recent list arrive with the features they depend on. The sidebar is a navigation landmark, and each section is a labelled group whose heading collapses it, and the switch is a pair of tabs (Left and Right move between them); the view and the collapsed sections last for the window (nothing is saved between runs yet).

- **Places** shows Home and the user folders that exist (the XDG user directories on Linux, Known Folders on Windows). **Favourites** are the freedesktop bookmarks file (`~/.config/gtk-3.0/bookmarks`), shared with other file managers, and **Ctrl+D** pins the current folder. A favourite whose folder is gone stays listed, and opening it shows the usual Folder not found state.
- A click opens the item in the active tab; a middle-click opens it in a background tab; the item of the current folder is marked. Right-click (or the menu key) shows Open and Open in New Tab, plus Rename, Move Up, Move Down and Remove from Favourites on a favourite and Add to Favourites on a folder. A folder in the file list has Add to Favourites in its menu too.
- **Favourites** are renamed in place (**F2**; an empty name restores the folder's own) and reordered by dragging a favourite onto another, with **Alt+Up** and **Alt+Down**, or from the menu. Up and Down move between the items of Places and Favourites.
- **Workspaces** (milestone 3) are named sets of folders that Rust keeps in the session store, shared by every window and restored with the session; they are never written to the bookmarks file. The section lists **None** and then each workspace, and marks the one the window uses. Choosing one makes the Favourites section show that workspace's folders under the heading “Favourites · Site”; choosing **None** shows the bookmarks again. The choice is per window, so one window can work in a workspace while another keeps the everyday list, and deleting the workspace a window uses sends it back to the bookmarks. While a workspace shows, Add to Favourites (menu or **Ctrl+D**), Remove from Favourites, reordering and drops edit the workspace's list instead of the bookmarks; its folders have no labels of their own, so they cannot be renamed. A missing folder behaves like a missing favourite.
- A workspace's right-click menu (or the menu key) has Open All in Tabs (each folder opens as a tab beside the active one, in order, the first becoming current), Rename and Delete Workspace. **F2** renames in place (a taken name asks again), **Delete** deletes, and Up, Down, Home and End move between the items; each change is announced.
- **Devices** (milestone 5, slice 17) lists the volumes the `volumes` plugin reports, between Places and Favourites: what is mounted, what is locked, and what a person can mount (the system's own unmounted partitions are left out). Each row shows the name, the free space written as text (“125 GB free of 500 GB”) under a thin usage bar, and “Almost full” in words from 90% used, on a line of its own so a narrow sidebar or a long translation wraps it rather than cutting it off (the whole caption is also on the row's tooltip), where the bar is also hatched, so colour is never the only signal; a volume that is not mounted says “Not mounted” and a locked one “Locked”. Clicking a mounted volume opens it in the active tab; on one that is not mounted it mounts it, and on a locked one it asks for the passphrase. Mount, Unmount, Eject and Unlock buttons follow the row, only those the volume allows and the plugin reports as working here (otherwise they are hidden, and Settings → Integrations → Services says why; with no list at all the section is not shown). Unmount and Eject are different: Eject unmounts everything on the drive and powers it off when it allows. The Unlock dialog asks for a passphrase; a wrong passphrase says so and asks again, and a right one mounts the volume. With _Remember encrypted-volume passphrases_ on (Settings → Integrations, off by default) and a keyring that answers, the dialog also has a _Remember in keyring_ checkbox, unticked every time: the passphrase is kept in the system keyring under the volume’s container UUID, the volume then unlocks and mounts by itself when plugged in (once per plug-in, and a wrong remembered passphrase leaves it locked for the person to unlock by hand), and a _Forget the saved passphrase_ button follows the row of a remembered volume. With the switch on but no keyring running, or a locked one, the dialog says why it cannot remember; with the switch off it says nothing of it. If unlocking worked but the passphrase could not be kept, the status bar says so. A volume that is busy says what is using it (“Could not unmount Backup because bash is using it.”) in the status bar and to screen readers. The list follows plugging and unplugging within a second, announcing “Camera connected” and “Camera removed”; every action is announced politely, and Up, Down, Home and End move between the rows like the other lists.
- **Folders** (its own view, so choosing a place never moves it) is a tree that opens down to the current folder and follows the active tab. A folder's children are read only when it is expanded, and the tree lists hidden folders only while the tab shows hidden files. It follows the tree keyboard pattern: Up and Down move, Right expands (then enters), Left collapses (then goes to the parent), Home and End jump, Enter opens the folder in the tab, and typing the first letters of a name jumps to it. A folder with more than 2000 sub-folders shows the first 2000 and says so.

### 5.5 File view

- **View switcher:** List and Grid buttons at the right end of the status bar (Ctrl+2 and Ctrl+1; Columns, Compact and Disk usage take Ctrl+3 to Ctrl+5 when they exist). The choice is kept by the folder it is made in (§5.3b), or, with Settings → General → _Remember each folder’s view_ off, is the window's session choice and every folder shows it.
- **Grid:** icons with a size slider (48–256 px, in the status bar beside the switcher while the grid is shown), names under them, thumbnails (below) and later folder peeks (a 2×2 mosaic of contents). The grid fits as many columns as the width allows and is virtualised by row. Arrow keys move one item sideways or one row up and down, Page Up and Page Down move by the visible rows, Home and End go to the ends; selection, type-ahead, Enter and the context menus are the list's. A folder too large for the webview's scroll height shows the same "Showing the first N of M" banner, counted in rows of columns.
- **Thumbnails (milestone 5, slice 9):** an image, video or document shows a picture of itself in place of its file type icon: in the grid at the icon size, in the list when rows are tall enough (the Roomy density and touch mode; the usual rows keep icons so a long list stays dense), on the Shelf, and on the front card of the drag stack. They are made as the folder is scrolled: what is in view and a screen either side is asked for, in view first, a scroll asks for the new rows and withdraws the ones left behind, and a pane that closes withdraws everything. They are the same files other file managers make (the freedesktop.org thumbnail cache on Linux, the shell's thumbnails on Windows), so a folder Nemo or Nautilus has already shown is instant. A file with no thumbnail, one that is too large (Settings → Previews & thumbnails sets the limit, 50 MB by default), one that cannot be read and any file that is not on this computer keep their icon; nothing is hidden. Folders keep their icon until folder peeks arrive. A thumbnail is decoration: the name stays the item's label, and it fades in unless reduced motion is on. Settings → Previews & thumbnails has **Show thumbnails** and **Largest file to make a thumbnail of**; where the system cannot make thumbnails the page gives the reason and offers neither.
- **Icons:** each entry's icon follows what it is, decided from its name (a few well-known names such as Makefile, then the extension, ignoring case), so a PDF, a spreadsheet, a Markdown note, a shell script, a font, a disk image, a certificate, an e-book, a 3D model, a package and a text file each look different; a file with the execute bit that is not otherwise known shows as an executable, and a broken symbolic link shows as a link. The Kind column names the same type. Sorting and grouping by kind still use the broad kinds (folders, images, audio, video, archives, code, documents, other), so finer icons never reshuffle a listing. The user's own standard folders (Home, Desktop, Documents, Downloads, Pictures, Music, Videos, Templates, Public and Projects) show a small mark inside the folder, in the list and grid, the Places and Favourites in the sidebar and the Folders tree. The set the icon is drawn from (the Waypoint glyphs, Portage artwork in the chosen folder colour, or the operating system's own icons for the entry's type) is the Appearance setting in §9 and follows it live in the list, the grid, the sidebar, the Shelf, the drag stack, the thumbnail placeholders and the Inspector, without reloading the folder. The Waypoint set's weight and fill follow the icon style (§9).
- **Empty-space menu:** right-click the file area (or press the menu key with nothing focused, or Ctrl plus the menu key anywhere in the list; the list also ends with a strip of blank space, so a full folder still has somewhere to click) for Sort by (Name, Size, Modified, Kind), Descending, Folders first and Show hidden files (Ctrl+H). The sort applies to the open folder and carries to folders the tab opens next; Show hidden files applies to every open tab.
- **List:** sortable, resizable, reorderable columns. Plugin columns (git status, media info) sit beside built-ins; the Git column is built (§5.3b), and so is the Storage class column on S3 (§7), which reads the keyed `attributes` any provider can put on an entry.
- **Sort and group:** the empty-space menu's _Group by_ section (a heading of its own after the Sort by items, so Name and Size appear once under each) and the Action bar's Sort menu, which ends with the same groupings, divide the listing into headed groups by **Kind** (folders, images, audio, video, archives, code, documents, other files), **Modified** (Today, Yesterday, Earlier this week, Last 7 days, Last 30 days, This year, then each earlier year, then Unknown date; calendar days in the local time zone, weeks starting on Monday), **Size** (Unspecified for folders, Empty, Tiny under 10 kB, Small, Medium, Large, Huge, Gigantic over 128 MB), **Name** (the first letter, with digits and symbols together) or **Type** (folders, names with no extension, then each extension), or by nothing (_No grouping_, the default); the one in use is checked. Grouping comes first in the order and Sort by orders the rows inside each group; a group column that is also the sort column follows its direction (Descending reverses the groups), Modified groups read newest first unless the sort is an ascending Modified, and with Folders first on the Folders group of Kind and Type stays at the top. Rust works out the groups from the sorted view and sends them with every snapshot and change, so a row that changes group (a new size, a rename, a watcher event) moves to its new group, and a group that empties loses its header. Each group has a header row with its heading and item count; a click on it folds the group shut or open. A folded group's rows are not shown, selected or reachable by the keyboard, and folding deselects them; Select All, Invert Selection and a Shift range leave them out. The arrow keys step over the header of an open group and stop on the header of a folded one; in the list Left from an entry, and in the grid Left from the first cell of a group, steps up onto its header, where Left folds, Right opens, and Enter or Space does either. Headers are `group` rows named “Today, 3 items, expanded” and are not counted among the list's rows, so a screen reader counts the entries. The sort and the grouping are the window's: they are saved with its view, restored with the session, and every folder the window opens next uses them (a folder already open keeps its own until it navigates). The Trash is never grouped.
- **Times:** the Modified column follows the system's 12/24-hour clock setting (and changes live when it changes), not just the locale's convention; where the setting cannot be read, the locale decides.
- **Columns (Miller):** hierarchical navigation with a preview column at the end.
- **Disk usage:** a treemap or sunburst of the current folder, with list parity.
- Selection works by click, Shift/Ctrl, rubber-band, and type-ahead (jump to a match; type `/` for an inline filter).
- **Inline rename:** F2 or Rename in the item menu. The first selection stops before the extension (a folder's whole name is selected). Enter renames; Escape or a click elsewhere cancels. What is wrong with a name shows under the field while typing, and a name that is taken keeps the field open ("A file named … already exists"); nothing is overwritten. Changing the extension asks first, with Keep as the default. With several items selected F2 renames the focused one; Ctrl+F2 opens batch rename.
- **New items and duplicate:** F7 creates a New Folder and Shift+F7 a New File (each takes the first free name, "untitled folder" or "untitled file", then opens in inline rename; Escape keeps the default name, and Enter renames it as one more undoable step; the same entries are in the empty-space menu under New). Ctrl+Shift+D duplicates the selection beside the originals as "name (2)", "name (3)" and selects the copies. These commands are hidden in a location nothing can be written to. Ctrl+Shift+N stays New Window.
- **Clipboard:** Ctrl+C, Ctrl+X and Ctrl+V copy, cut and paste files (Cut, Copy and Paste are in the item menu, Paste after New in the empty-space menu; Cut and Paste are hidden in a location that cannot be written to, Copy stays, and Paste is disabled while the clipboard is empty). A cut dims its rows, in every window that shows them, until it is pasted or replaced by another Copy or Cut. Ctrl+V pastes into the folder being shown, whatever is selected; on a folder, **Paste Into Folder** in its menu pastes into it. A cut moves and then empties the clipboard; a copy copies, and pasted beside its own originals it makes copies named “name (2)”. A folder cannot be pasted into itself, and a cut pasted where it already is says so and keeps waiting. Copy and Cut also put the files on the system clipboard, and files copied in another application (Nautilus, Explorer) paste here, a cut as a move (§13b); Delete moves the selection to the Trash (no question by default, and an Undo toast follows; where a volume has no Trash it offers Delete Permanently, saying why) and Shift+Delete deletes it permanently (always after a confirmation that names up to five items and says it cannot be undone). Ctrl+Z and Ctrl+Shift+Z undo and redo. Pasting never overwrites without asking (§8).
- **Quick Look:** Space on the focused entry opens a preview over the window (it is part of the window, not a window of its own), and Space or Esc closes it and puts the focus back on the entry. Left and Right (and Up and Down in the grid, a row at a time) step to the previous or next item without leaving it, skipping sockets and pipes; the header shows the name and a position such as “3 of 12”, which is announced as it changes. Images are shown scaled to fit (their thumbnail first), text as monospace (the first 256 KiB, with a notice when the file is longer), audio and video with the system's own controls (seeking works), and PDFs, fonts, archives and everything else as their large thumbnail with the name, kind, size and modified time; a folder shows its name and kind. A preview that cannot be shown says so in words and still shows those facts, never a blank panel. **Open** opens the item as a double-click does, and **Open With…** appears where the system can list applications. Space does nothing while renaming or typing in a field, and in the Trash. Hover-to-peek is not built yet.
- **Empty states:** an empty folder, no search results, a remote disconnected (with reconnect), and permission denied (with "Open as administrator").

### 5.6 Split view (joined tabs)

A split is two or more tabs joined together. They sit in the tab strip as one bridged pill, and each half is still a normal tab that can be clicked. Each keeps its own history. Pinning, colour and group apply to the pair.

- **Create:** drag a tab into the content area and release over its left, right, top or bottom region (§13c); hold a tab over another tab; right-click → Split With; F3; or drag a folder to a content edge.
- **Toggle (F3 or the split button):** creates a paired tab on the same folder and focuses the new pane. Toggling again **closes the pane it created** (whichever pane has focus) and leaves the original tab, with an “Undo” toast that puts the pane back with its history and sizes (the toast stays about 8 seconds, waits while the pointer or focus is on it, and Escape dismisses it); the closed pane keeps its history for Reopen Closed Tab. A pair you joined by hand is only separated, never closed.
- **Separate:** drag a pane header up to the tab strip, right-click → Separate Tabs, F3 again, or close one half (the other stays as a normal tab).
- **Layout:** side by side or stacked, more than two panes, draggable dividers, double-click a divider to reset. A pair's panes each have a header (folder, a grip that is dragged up to the tab strip to separate, a close button, and “Active” on the focused pane). A divider is a separator: drag it, or use the arrow keys along its axis (2%, or 10% with Shift), Enter to reset; a pane never goes under 10%. Sizes are saved when the drag is released, and Escape abandons a drag.
- **Panes:** the focused pane is the active tab. Click in a pane, or F6 (next) and Shift+F6 (previous), to focus it; the path bar, sidebar, status bar and navigation follow it. Each pane keeps its own selection and scroll.
- **Tear off:** drag a pane header out of the window to move one half; drag the joint between the tabs to move both. The tab menu's Move to New Window and Move to Window ▸ on one half do the same as dragging its pane header and take that half alone, leaving the other as a normal tab; the joint's menu (and the same items on the pair's header) take both.
- **Close:** closing a half asks first if the other half is the target of a running operation.
- **Copy and move between panes:** with a selection in one pane of a pair, **F5** copies it to the other pane's folder and **Shift+F5** moves it, with no question; the item menu has the same two as Copy to Other Pane and Move to Other Pane, shown only in a pair. With no pair, or when the other pane's folder cannot be written to, F5 and Shift+F5 open Copy To… and Move To… instead (§5.3b); with nothing selected they only say so. In a pair of more than two panes the target is the next pane. Conflicts and failures are the queue's (§8).

### 5.6a Split pane (original notes)

- Available per tab, vertical or horizontal. The divider can be dragged, and double-clicking it resets to 50/50.
- F6 or clicking a pane makes it active, and the active pane gets an accent outline.
- **Pane sync:** a toggle that mirrors navigation in the other pane by relative path, so you can compare the same subtree on local and remote.
- F5 copies to the other pane and Shift+F5 moves to it (F6 and Shift+F6 switch the active pane). Keys are configurable.

### 5.7 Inspector

An optional panel at the right edge of the window, after the panes (and after the Shelf where both are open), with tabs **Preview** (a thumbnail or rendered preview with a short summary: name, kind and size), **Properties** (the full detail) and **plugin panels**. F11, View ▸ Inspector and the command palette show and hide it; it reopens on the tab last used, and its left edge is dragged (or moved with the arrow keys; double-click restores the default) to resize it. The width and the tab last as long as the window does, as the Shelf's do. It follows the active pane's selection, shows the facts the listing already holds at once and reads the rest a moment after the selection settles, so holding an arrow key through a folder reads nothing, and a closed Inspector reads nothing at all. The tabs are a proper tab list (Left, Right, Home and End move between them) and each is a labelled tab panel.

- **Preview tab:** an image is drawn from the file itself once the selection settles (its large thumbnail stands in while it loads, and stays for a picture over 20 MB or one the webview cannot draw); text shows the first 16 kB in a monospace block and says when it is cut short; audio and video get a player that fetches only its metadata until played; anything else keeps its large thumbnail or its icon, with the name, kind and size under it. A folder shows its icon, name and item count, several items show a count, and nothing selected shows the current folder.
- **Preview tab:** the picture block (168 × 126, larger for an image, video or audio player), the name centred with the kind and size under it, then Kind and Size rows and, for text, the start of the file. Several selected show a stacked-folders block with the count and total size; nothing to inspect shows a centred “Nothing selected” with a hint.
- **Git tab (milestone 6):** the third tab, there only while the folder shown is in a Git working tree and Settings → General → _Show Git status_ is on (otherwise the panel is on another tab and no Git tab is listed). It names the repository, the branch and its upstream, the counts (staged, not staged, untracked, in conflict) and any merge, rebase, cherry-pick, revert or bisect in progress; for the selected item it says its status in words (_Modified, staged; Modified, not staged_), what has changed in it since the last commit (files changed and lines added and removed, as `git diff --stat HEAD` counts them, with binary files counted apart and a note when some were too many or too large to read) and the five newest commits that changed it (summary, short id, author and date). The history is read a moment after the selection settles, bounded to the most recent 5,000 commits (the tab says when older ones may exist), so holding an arrow key through a folder reads none. With nothing selected it shows the folder's, and with several items selected it says the history shows for one at a time. The tab is read only: it has no button, and staging and committing are the Git extension's (milestone 8). It is chosen like the other tabs (arrow keys, Home and End).
- **Properties tab:** leads with a hero (a rounded picture block, the name centred and bold, and the kind and size beneath), then the facts as aligned rows, each label at the start and its value at the end, with the name as a full-width field above them: name (with a Rename… button that starts the ordinary rename; the Inspector does not edit names itself); kind; size (a folder shows “Calculating…” and updates from a cancellable background count, which stops when the selection changes, the tab changes or the panel closes; only the finished total is announced to a screen reader); on disk; location; modified, created and accessed; owner and group; permissions (`rwxr-xr-x (0755)`); link target (or “Broken link”); content type; free space (folders); and the default application (a local file, where the system can list applications; “No application” when there is none). A field the provider cannot report at all reads “Unavailable”, and a field the entry simply does not have is left out. Media info and Git status when those plugins are on; tags and a comment (editable); and permissions with toggles and an “Apply to enclosed items” option for folders arrive with the features behind them. A checksum is on request in the Properties window (below).
- **Several items selected** show a count and the total size of the files among them (folders are not walked, and the panel says so). **Nothing selected** shows Properties for the current folder: its name, kind, location, how many items it holds and the free space on its volume; a recursive size is for a folder that is selected.
- **Type-specific details:** images show dimensions, megapixels, colour space, bit depth and camera details; video shows duration, resolution, codec and frame rate; audio shows bitrate, sample rate, artist and album; PDFs and documents show pages, words, author and encoding; code shows language and lines; archives show item count and compression; folders show what they contain. Media details come from the Media Info plugin. Preview shows the first three.
- Right-click ▸ Properties (on an item or on empty space) and the command palette's Properties always jump to the Properties tab.
- **Properties window.** **Alt+Enter**, the item menu's _Properties in a Window_, the palette's _Properties in a Window_ and the Properties tab's _Open in a window_ button open a standalone Properties window for the one selected item, or for the current folder when nothing is selected (several selected items are not one subject, so the command says "Select one item, or none for the folder"). The window is frameless with the shared title bar, shows the same facts as the Properties tab, and adds what the narrow panel leaves out: the permissions taken apart (who may read, write and run it, with the octal mode and any setuid, setgid or sticky bit), every time in full with its ISO 8601 value in UTC, the exact size in bytes and what is allocated, the read-only and hidden flags, and, for a link, what it points at and what that is. It shows only what the details report: a field the provider cannot report reads "Unavailable", and the inode, the file system and extended attributes arrive when the details carry them. At most four Properties windows are open at once; asking for the same item (or folder) brings its window to the front, and asking for a fifth says so in the status bar. A window follows its item: if it is renamed the window shows the new name, and if it is removed the window says "{name} no longer exists" and shows nothing as current. Esc closes the window.
- **Checksum.** For a file (or a link to one) the window offers a checksum, calculated only when you press _Calculate checksum…_ and never for a folder. SHA-256 is the default and BLAKE3 is the other choice (the algorithms copy verification uses). A file above 1 GiB asks first, since the whole file is read. It shows progress, can be cancelled, and the digest can be copied. Only the finished digest is announced to a screen reader. The run is cancelled if the file changes under it or the window closes.

### 5.8 Status bar

Shows the item count, the selection count and size, free space on the current volume, the List and Grid view switcher at the right end (D23), an ops queue ring (progress and count, click to open; see Operations below), and plugin status items such as the git branch (built: §5.3b) and remote latency.

- The selection count is immediate; the size is the sum of the selected files (folders add nothing, it is not recursive) and is worked out in Rust, so it arrives a moment later and dims while a newer one is on its way. Free space is hidden where the volume cannot report it.
- The bar announces the selection count politely to screen readers, and reports a failure such as a file that would not open.
- **Open:** Enter or double-click opens a folder in place and a file in its default application. The read-only context menu on an entry offers Open, Open in New Tab (folders) and Copy Path (the path as Rust displays it, which may be lossy for names that are not valid UTF-8). Right-clicking an entry that is not selected selects it first, and the menu acts on the entry under the pointer. The menu key or Shift+F10 opens it for the focused entry.

### 5.8a Overview

A place, not the Start page: **Overview** (`overview:/`) answers where the space went and what is plugged in. It opens from the sidebar (Places, above Home) and the command palette ("Open Overview"); the Start page may show compact Devices cards that link to it.

- **Headline stats:** Capacity (local, real volumes only, and it says what it counts), Free, Home (its size and its share of the used space) and Volumes (the count and their file systems). Home reads "Not measured yet" until the directory-size scan can report it, and "Measuring…" while it runs. _Built in milestone 5 (slices 23 and 25):_ everything in this section; the Home size, "Your files" and Biggest folders in Home come from the directory-size scan, and the last result is shown at once with "as of <time>" (the Home stat's note and the section's header) while a fresh scan can run.
- **Volumes:** a card for each (disk images are left out), with its name, its real file system (ext4, btrfs, NTFS, exFAT), a "System" or "Removable" badge (a network share says "Network", an optical disc "Optical"), its size and free space and an exact **Used / Free** bar. The volume that holds Home may show **Your files** within Used; the rest is "Everything else". There is no "apps and system" segment, because those are ordinary folders on Linux and Windows. A network volume shows no bar until it is measured on request (a Measure button); where the volumes service cannot list volumes the page says why and shows the volume that holds Home from the file system's own numbers; space that cannot be read shows "Size unavailable"; a locked encrypted volume shows a lock and Unlock.
- **Trash:** the item count and, when known, its size ("Not measured" when it could not be added up, never zero); Open and Empty (Empty keeps its confirmation). Where the Trash cannot be listed (the Flatpak portal can only trash) it says so, in the Trash service's own words. A note says the Trash on other drives is counted too but has not been verified on every kind of drive.
- **Biggest folders in Home:** the largest folders with a size bar each, the share of Home, and a remainder row "Other files and folders, including hidden". A cancellable scan fills it in one folder at a time and shows its progress; the last result is kept and labelled "as of" a time, the scan starts when Overview opens (Settings → Previews & thumbnails turns that off) and "Measure now" starts it on request. It never leaves the volume, skips symlinks and never downloads a cloud placeholder (Windows counts it as zero). A row opens its folder. _As built (slice 25):_ the rows appear as the scan reports each folder, largest first, each a button (Enter opens the folder in this tab) named in full ("Backup, 128 GB, 21% of Home") with its size and share written beside a decorative bar, and the remainder row last, hatched and not a button. **Measure now** starts a scan and becomes **Cancel** while it runs; Cancel stops it at once and keeps the folders reached, and a scan also stops when the tab leaves Overview (it closes or moves to another location). Only one scan runs at a time. A cached result under an hour old is shown without scanning again; an older one is shown while a fresh scan runs. A line says how many cloud-only files were counted as empty and not downloaded, when there were any. While a scan runs the status bar shows **Measuring Home** with the folders done; it opens Overview, and its × cancels the scan.
- **Accessibility:** every bar has a text equivalent ("Backup, 128 GB, 21% of Home"), never relies on colour alone (a pattern and a numeric legend), and keeps 4.5:1 for text and 3:1 for graphics; scan progress is announced politely once.

**Milestone 4 also ships drags to and from other applications** (slice 13), where the system allows them (Settings → Drag & drop says why when it does not). _Drops from other applications and from another Waypoint window_ act on every target above except the Trash, with the same pill and spring-loading, and become a copy, move or link job over the files' exact names (spaces, `#`, `%` and names that are not valid UTF-8 survive); a drag of text or a link is ignored, and a drag that leaves the window clears the highlight. A folder dropped into itself, or a move onto the folder the files are already in, is refused as a paste refuses it. _Dragging out:_ when a drag of rows leaves the window it continues as the system's drag of those files (copy, move and, where the system has it, link), so another application receives them as URIs; the originals are left alone unless that application moves them, which it does itself (no job runs in Waypoint), and the result is read out. A drag that cannot be handed over stays in the window with a notice. Platform notes: on Wayland the compositor does not tell an application which modifier keys are held during a drag, but it chooses the drag's action from them among the actions the source offers, and Waypoint follows that action: holding Shift while dragging from a file manager that offers a move moves the files, and with no key the default rule decides, which for files from another application is a copy, since a drag in does not say what its source allows (a move is carried out as a move job, with its conflicts, verification and Undo); Ctrl and Alt cannot be read there, so "Always ask" in Settings → Drag & drop or the right button offers the picker at the drop; Wayland has no link action for a drag out; on Windows a drag out is a modal system drag that Windows draws; dropping on the terminal is not built yet.

It holds references (a location, its name and the folder it sits in), not copies, and the same list is shared by every window and kept across restarts (Settings → Drag & drop → "Keep the Shelf between sessions" turns the saving off; the list still works for the session). It holds at most 500 items; adding past that is refused with a message and adds nothing. Items are grouped by the folder they came from (newest first, each group collapsible with its count) and show as tiles in a strip that wraps onto more lines as the dock grows (a group's chip, then its tiles), each with an icon, the name, the origin and a remove button; a file that is no longer there is dimmed and marked "Missing" (looked at only while the panel is open: when it opens, when items change and when the window is focused again). Add items by dragging rows onto the dock (the pill says "Add 3 items to the Shelf" and nothing is ever refused but the cap), with "Add to Shelf" in a file's menu or the Edit menu, or from the palette. Files dragged in from another application or window can be dropped on the panel too, and are added the same way. Drag items out onto folder rows, sidebar places, tabs and panes: the usual default rule decides move or copy (the planner says which volume), Ctrl, Shift, Alt and the right button work as for any drag, and the Trash, the + button and group chips refuse them. Items dragged out of the window continue as the system's drag of those files, as a drag of rows does. After a finished move the entries whose files left their folder are taken off the Shelf (an entry whose file is still there, because a conflict skipped it, stays; Undo restores the file, not the entry). Select with click, Ctrl and Shift (or Space, Shift+arrows and Ctrl+A); Left and Right move along the strip and Up and Down between its lines; Delete removes the selected items from the Shelf, never a file, and the tooltips and messages say so; the panel menu's Clear Shelf asks first when there is more than one item. The item menu has Open (a folder opens in the pane; a file is shown in its folder, because files open from a listing), Reveal in Folder (its folder in a new tab with the file focused), Copy (the files onto the clipboard for a paste), Copy Path and Remove from Shelf. The dock's height is dragged by its top edge or set with Up and Down on it, is capped at 60% of the content column, and lasts as long as the window. The pop-up when a drag pauses near the edge and "Send to…" are later; file items show thumbnails (see Thumbnails above).

**The Shelf window (as built).** The dock's header has an Undock button (so do View ▸ Undock Shelf and the palette's Undock Shelf), which moves the Shelf out of every Main window into one window of its own, the Shelf window: the same panel, the same items, groups and selection rules, and the same drops, drag-out, item menu, keys and screen-reader names, inside the shared title bar. There is at most one. While it exists no Main window keeps a dock, and Ctrl+B, the status bar's Shelf button (pressed while the window is on screen) and Focus Shelf raise the Shelf window, or hide it when it is already in front; Ctrl+B in the Shelf window hides it, and a hidden Shelf window is still undocked. Its Dock button (View ▸ Dock Shelf, the palette's Dock Shelf) puts the Shelf back in the Main windows' docks, and so does closing the window; either way the dock comes back open. The window's place, size and whether it stays on top of other windows are kept with the session and restored with it (a start that restores no windows docks the Shelf again), and its title bar has an Always on Top button wherever the system can keep a window on top (not on Wayland, which has no protocol for it; the Services report says why, and the compositor's own window menu has one). Items are the one list in Rust that every window follows, so a change in the Shelf window shows in every Main window and the other way round. If the system cannot make the window, the Shelf stays docked and a message says so. Dragging the dock's header out to make the window, and dropping the window back on a Main window, are later. While files from another window are held over the Shelf window, the whole window is the drop target: an accent edge round it and a “Drop to add to the Shelf” hint, which go when they leave or are dropped.

## 7. Remote & virtual locations

| Provider     | URI                                                                            | Notes                                                                                          |
| ------------ | ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| SFTP/SSH     | `sftp://user@host:port/path`                                                   | Key agent, known-hosts prompt, jump host, "Open terminal here" over SSH                        |
| SMB          | `smb://domain;user@host/share/path`                                            | Domain auth, share browser (`smb://host/` lists the shares)                                    |
| WebDAV       | `davs://host/path` (`dav://` for HTTP)                                         | Nextcloud preset (`remote.php/dav/files/<id>/`, app passwords); Digest, Basic or token sign-in |
| S3           | `s3://bucket/prefix`                                                           | Endpoint preset (AWS, MinIO, R2, B2, Wasabi, Spaces), storage class column                     |
| Git          | `git+file:///repo!/path?rev=main` or a local repo overlay                      | Status column, branch in the status bar, stage and commit actions (plugin)                     |
| Archives     | `archive:{archive's location}!/path`, opened from `*.zip`, `*.tar.*` or `*.7z` | Read-only, or read/write where the format allows; archives inside archives and on servers too  |
| Cloud drives | Plugin-provided                                                                | Nextcloud and Google Drive samples                                                             |

**Experimental (D167).** The remote protocols have not been tried against real servers beyond throwaway test servers, so each is off until you turn it on, on **Settings → Experimental**: one switch each for **SFTP**, **SMB**, **WebDAV** and **S3**, every row marked Experimental. Archives as folders, Git and the local file system are not gated. A change takes effect at once, with no restart, and a protocol that is off has no provider, so nothing connects, listens or reads a credential for it. With a protocol off it is missing from the Connect dialog's protocol list; its saved connections stay in the Network section, dimmed, with "Turned off in Settings → Experimental"; an address in its scheme, whether typed, from a bookmark, history or the command line, opens as a state that says the protocol is turned off, with a link that opens the page, and an operation that names one fails with the same reason; and the Services panel lists the protocol as "Turned off in Settings → Experimental". Turning the switch off ends that protocol's logins. While every protocol is off the Network section and Connect to Server… are not shown. A protocol the build does not include has its switch dimmed and the Services panel says "Not included in this build".

**SMB.** `smb://host/` is the share browser: the server's shares as a folder you open one share of, with no network neighbourhood. A location may name a domain (`smb://WORK;me@files/Projects`); Waypoint asks for the password when it connects and can remember it in the system keyring, and it signs in with NTLM. Kerberos single sign-on and servers or shares that require encryption are not supported on Linux yet, (the Services status panel gives the reason). On Windows the operating system's own SMB client does the work (UNC paths), so domain logins, Kerberos, signing and encryption behave as in Explorer, and a mapped drive stays a local folder in Devices. A folder of 100 000 entries on an SMB server shows its rows only once the server has sent all of them (about a second on a LAN).

**S3.** (#295, D163) `s3://bucket/key` shows a bucket as a folder and the `/` in keys as subfolders, on AWS and on any S3-compatible service (MinIO, Cloudflare R2, Backblaze B2, Wasabi, DigitalOcean Spaces: the Connect dialog's presets fill the endpoint, which is written `?endpoint=https%3A%2F%2Fhost` in the address). The login is an access key id and secret, asked for like a password and kept in the keyring if you choose; a session token (for temporary credentials, kept for the session and never remembered) and a region can be set, and the AWS environment variables and `~/.aws` files are offered to AWS buckets by the provider but not by the app, whose access key is the connection's own. A bucket in another AWS region is found by following the service's redirect. A folder exists while something is in it; New Folder writes a `key/` placeholder, removed when the folder is deleted. S3 has no rename, so a move or a rename copies on the service and then deletes (item by item, not atomically; the provider reports `rename: None` and the engine does it), and a copy within one service never sends the data through Waypoint. Large files upload in parts, and a failed or cancelled upload is aborted so nothing is left (or billed). Folders list a page at a time, the first rows at once; 100,000 keys list in about 0.36 s against an in-memory service on loopback, within the 0.5 s LAN budget, and a real service is limited by its 1,000 keys per page. Files in Glacier Flexible Retrieval or Deep Archive are listed, and reading or copying one says it needs a restore, which Waypoint never starts. Keys with an empty name, `.` or `..` are not shown. The **Storage class column** is hidden by default and offered in the header menu in S3 folders (not a sort key); each cell says the class in words, with a note for an archive class. An archived file, and a clock that is off by more than the service allows, have errors of their own ("needs a restore", "this computer's clock is off") in both the folder state and a job's dialog. **In the app (D169):** S3 is a working switch on Settings → Experimental like the others, with a Connect dialog form of its own (below); the confirmation before a move on S3 is the form's note that a move copies and then deletes, and a prompt in the operations dialog is not yet built.

**Connect dialog:** pick a protocol, fill host, user and auth, test the connection, then save to the sidebar (optionally into a workspace). Thumbnails are off for remotes by default and can be turned on per remote. As built (#307, D166): **Previews** in More options is Off, Small files only (images up to the server's size cap, 2 MB unless set from 1 to 100 MB) or Always (also a large photo's own small preview, from its first 64 KB); Settings → Previews & thumbnails lists the saved servers with the same choice; a server that is not saved has no previews, and no file is downloaded whole for one.
**Connect dialog:** pick a protocol, fill host, user and auth, test the connection, then save to the sidebar (optionally into a workspace). Thumbnails are off for remotes by default and can be turned on per remote. As built (#286, D159): **Connect to Server…** is in the File menu, the + button's menu and the command palette (and in the Network section, #287). The dialog starts on its **Address** field: typing `sftp://me@nas.lan:2222/srv` fills Host, Port, User and Start folder as Waypoint reads it, says when a password written in it was not kept, and says what is wrong with text that is not a server address or names a protocol Waypoint cannot use here; the fields can also be filled one by one (Protocol lists only the protocols available; Host suggests the hosts named in `~/.ssh/config`). **Sign in with** is Automatically (the SSH agent and key files, then a password asked for), Password (typed in the dialog or asked for when connecting, with **Remember in keyring** where a keyring answers, or a line saying why it cannot) or Key file. **More options** has the jump host, the start folder, Refresh every N seconds and Show previews. **Test** connects without saving and says the outcome in words (connected, or why not: host not found, refused, no route, offline, timed out, sign-in refused, host key not trusted), keeping every field; **Save** keeps it in the Network section (a refused field has its message under it); **Connect** connects and opens the server in a new tab, and a server connected to without saving it is listed under Recent servers. The list beside the form shows the saved connections, each with Edit (choosing it loads the form), **Duplicate** (“NAS (copy)”) and **Delete**, which asks first, starting on Cancel, and can also forget the saved password. A question on the way is a dialog of its own over the Connect dialog: **Sign in** (the password, a key's passphrase, a keyboard-interactive round's questions or an access key, with Remember where it can be kept), **Trust {host}?** for an unknown SSH host key (the key type and SHA-256 fingerprint, with Cancel, Trust Once and Trust and Remember, starting on Cancel), **The key of {host} has changed** (a strong warning, the recorded and the offered key side by side, starting on Cancel, connecting only through **Trust the New Key**), and **Trust the certificate of {server}?** for a TLS certificate the system does not trust (Trust Once, or Trust for This Connection, starting on Cancel).

The form follows the protocol chosen (D168). **SFTP** is as above, with the key file and the jump host that only SSH has. **SMB** asks for an optional **Domain** (saved with the user as `domain;user`) and an optional **Share** (empty is the share browser, `smb://host/`), signs in Automatically (a remembered password, then asked) or with a Password, and has neither a key file nor a jump host; a domain with no user is refused before anything is sent. **WebDAV** (`davs://`, and `dav://` with a note that it is not encrypted) signs in Automatically, with a Password (sent as the server's choice, Basic for an app password, or Digest) or with an **Access token**, and has a **This is a Nextcloud server** box that selects the Nextcloud dialect and, with a host and a user, **Fill in my files folder**, which has Rust write `remote.php/dav/files/<user>` and reads it like a typed address. A way to sign in that the chosen protocol does not have goes back to Automatically, and a saved connection holds only the fields its protocol has. **S3** (D169) asks for a **Service** (Amazon S3, Backblaze B2, Cloudflare R2, Wasabi, MinIO, DigitalOcean Spaces or another S3 service), the one thing that service needs to find its endpoint (a region, an account ID, a server, or the whole endpoint; Amazon S3 needs nothing), an optional signing **Region**, the **Bucket** (the connection's host: a login is per bucket, and a service root has no address), the **Access key ID** and **Secret access key**, an optional **Session token**, and **Put the bucket in the path** (on by default for every service but Amazon S3); the folder in the bucket is the start folder. The access key id is saved with the connection and the secret goes to the keyring only when you choose Remember, never to `connections.json`; a one-line note says that S3 cannot rename, so a move copies and then deletes. A typed `s3://bucket/key?endpoint=…` address fills the form, and a login that asks again (no remembered secret, or one the service refused) asks for the key id and the secret in the sign-in dialog.

**Milestone 6 decisions (D146 to D152, D154 and D155; the design is `docs/architecture/remote-locations.md`).**

- **Addresses.** Each location has one written form: Waypoint tidies what is typed (the host's letter case, default ports, `..`), IPv6 hosts go in brackets, another S3 service adds its endpoint (`s3://photos/2026?endpoint=https%3A%2F%2Fminio.lan%3A9000`, shown as "s3://photos/2026 (minio.lan:9000)"), and the breadcrumbs start at the server, the share or the bucket. Up from the top of an archive goes to the folder that holds it, and from the top of a revision to the repository's folder (D149, D152).
- **Signing in.** Waypoint never writes a password, passphrase or secret key to its own files, locations, logs or errors. A password typed into a location is stripped and the path bar says it will be asked for. The SSH agent and key files are tried first; otherwise a sign-in dialog asks, with **Remember**, which stores the secret in the system keyring; without a keyring the login lasts for the session and the dialog says why (D147).
- **Host keys and certificates.** An unknown SSH host key asks in a dialog that starts on Cancel, with the key type and SHA-256 fingerprint, and accepting adds it to `~/.ssh/known_hosts`. A changed key never connects silently: a strong warning shows the host and the old and new fingerprints, starts on Cancel, and only an explicit **Trust the new key** replaces the old entry in `known_hosts`. An untrusted TLS certificate asks the same way and is remembered for that connection only (D148).
- **Remote tabs.** A remote location is kept in tabs, history, Recently Closed, workspaces, favourites and the Shelf like any folder. A restored session connects a remote tab only when it is shown; one that cannot shows its own state (Disconnected, Unreachable, Sign in needed, Timed out) with Reconnect or Sign in, never a prompt at start-up and never a blank view. An idle connection closes after five minutes and reopens when needed (D146). As built (#287): a server tab's icon is the server glyph with a state dot, and its description says “On a server:” and the state. While its login connects the folder says “Connecting to {server}…”; a folder that cannot be shown says why in words, with one action: **Reconnect** (disconnected, cannot be reached, not answering), **Sign In…** (the server asks for a login, or refused one) or **Review…** (an unknown or changed host key, an untrusted certificate), which asks in the same dialogs as the Connect dialog. Once a server's login is back, from there, the Network section or the Connect dialog, every folder on screen that failed for its connection opens again. The breadcrumbs start at the server, named after its saved connection when it has one. A password typed in a server address in the path bar is taken out of the text, the bar says it was not kept and will be asked for, and the next Enter goes there; the path bar offers the saved and recent servers as suggestions.
- **Saved connections.** A server can be saved under a name with its protocol, address, user, how it logs in (automatically, a password, or a key file), a jump host, the folder it opens at and its own options (previews, refreshing, timeouts); never a password. A server connected to without being saved is listed under Recent servers (the last ten), and hosts named in `~/.ssh/config` are offered as suggestions. A password typed when signing in lasts until Waypoint quits; with Remember it goes to the keyring once the server has accepted it, and a remembered password the server refuses is not tried again until the person signs in anew. Removing a saved connection can also forget its remembered password (D158).
- **Folders that are not watched.** A server folder refreshes when its tab is shown or its window is focused (when more than ten seconds old), on F5 and after Waypoint writes into it, keeping the selection and scroll position; a connection can refresh every N seconds (off by default); the status bar says the folder is not watched; and if the connection drops, the rows stay, dimmed, under the disconnected state (D150).
- **Transfers.** Copy and move between any two locations are ordinary jobs with progress, conflicts, verification and Undo, done on the server when both ends are on one server. A drop onto a remote copies by default and Shift moves. A time the server does not give shows as "unknown", and Replace if newer does not replace then. A failed transfer keeps what it sent and Retry continues from there where the server allows, or starts the file again and says so (D151, D62). As built (#305, D164): a move within one login is a rename (so a drop there moves by default), and a copy within one login is done by the server where it can copy; between a computer and a server, or two servers, the bytes stream through Waypoint, written under a hidden name and renamed into place, or written straight to their name on a server that only shows a file once it is whole. Modification times and permissions are kept where the destination can hold them, and a finished job says what was not kept. Copy To… and Move To… list the servers; the Operations list says which server a job uses; a server that asks for a login part way offers **Sign In…** in the error dialog, which connects and retries the item; and without verification each copy on a server is checked by its size. Undo of an upload removes the copy from the server, and refuses if it has changed there. As built (#306, D165): a lost connection part way is waited out: the job says "Connection lost, trying again by itself" with the reason and the try, and carries on when the server is back, asking only after about three minutes; a file stopped part way on SFTP or SMB carries on from what the server holds (the error dialog says so, or that this server must start the file again), and after a crash or quitting the next start offers each such transfer in turn with **Resume** and **Discard…** (which asks, naming the files whose partial copies go), as does the Operations list under **Interrupted transfers**; it never resumes by itself.
- **Archives.** Enter or a double-click on an archive opens it as a folder in the current tab, as it does a folder; Open in New Tab, Open in New Window and the middle button open it beside this one, as they do a folder (an archive is the one exception to D24's rule that an archive opens in a new tab: it now behaves like a folder), and Open With still offers the applications that can handle it. A zip, a tar (plain, or gzip, bzip2, xz or zstd compressed) or a 7z file browses as a read-only folder without being extracted: its folders open at once, a file reads as it is opened or previewed, and archives inside archives open the same way, on this computer or on a server. A compressed tar has no index, so a big one is read once to be listed and the tab says that it will take a while; an archive with more than two million entries says so instead of showing part of itself. Names are shown safely: a name that starts at the root or the top of a drive loses that, `..` is shown as `%2E%2E`, and an entry that would write through a link inside the archive is marked, so extracting never writes outside the folder it was given. A link that points outside the archive shows as broken. An encrypted archive asks for its password like a login (names are readable first unless the archive hides them too), a wrong password asks again, and the password is kept in memory only. A damaged or cut-short archive shows its own state, not an empty folder (D154).
- **Extract and Compress.** Extract puts an archive's contents in a folder named after the archive, unless the archive holds just one thing at its top, which goes straight in, so extracting never scatters files among what is there; it can also extract straight into the folder or always into a named folder. A name that is taken is a conflict (Replace, Skip or Keep both), a cancel leaves no half-written file under a final name, and Undo removes what was extracted. Entries with unsafe names, links that point outside the archive and devices are left out and listed, setuid, setgid and sticky bits are never set, and an archive that goes past the limits (by default more than a million entries, more than 100 GiB once extracted, or more than a thousand times its own size once past 1 GiB) asks before it goes ahead; the limits are set under Settings → Operations → Archives, travel with the settings export, and have a **Reset to defaults**. Compress packs the selection into one archive (zip, tar, tar.gz, tar.bz2, tar.xz or 7z) under a name chosen by the person, never containing itself, keeping links, permissions and times; Undo removes it (D155). Both are in the app (D162): **Extract Here** (beside the archive) and **Extract To…** (a folder chosen in the destination dialog) are on an archive's item menu and in the File menu; **Extract All** is the Action bar's button and File menu entry inside an archive, and extracts the whole archive at once into a new folder beside it named after it (a name that is taken gets the next free one, `name (2)`); **Compress…** is on the item menu and in the File menu for the selection in a folder that can be written to, and asks for a name and a format (zip, tar.gz, tar.xz, tar.bz2, tar or 7z; the name starts as the one item's name, and changing the format changes the end of the name) in a dialog. They run as jobs in the queue with its progress, conflicts and Undo. An archive past the limits asks first and says which limit; entries left out are counted in a notice; an encrypted archive asks for its password in the sign-in dialog and carries on.

## 8. Operations

- **Closing a half:** closing one half of a split asks first ("An operation is still writing to this folder") while an operation is writing to the other half's folder.
- **Ops queue:** every create, rename, duplicate, copy, move, link, trash, delete or verify is a job with progress, speed and an ETA, shown in a popover from the status bar that can be popped out into a window; later milestones add upload, extract and more. Jobs can be paused, resumed, cancelled and retried, and queued jobs can be reordered (Alt+Up and Alt+Down in the list); a speed limit and job priority are described below, and scheduling and Pause all follow. The ring at the right of the status bar, before the view switcher, is always there: a quiet glyph when nothing is listed, a ring that fills with the overall progress and the number of unfinished jobs while any run, a dot when a job waits for you (attention) or has failed, and a check when everything has finished. It never animates beyond a short fill (none under reduced motion), and jobs not yet sized show a still quarter. Enter, Space or a click opens a popover over the bar: each job shows its title, source and destination, state, progress with speed and time left, and the actions its state allows (Pause, Resume, Cancel, Retry, Dismiss, Show in folder, Resolve… for a job waiting on conflicts or an error); Clear finished empties the list; Pop out opens the single Operations window, which lists every job the same way. A finished job that can be undone shows a toast with Undo, and the polite live region announces a job starting, waiting for you, failing, being cancelled or finishing, with the others still in progress, and 25, 50 and 75 % of a job that has run for three seconds.
- **Speed limits and priority (D157):** Settings → Operations has _Limit copy and move speed_ (off by default) and a _Speed limit_ in MB/s that holds every copy and move together under it; _Operations running at once_ (1 to 8) sets how many jobs run together. A copy or move that has not finished has a _Speed limit_ menu on its row, in the status bar popover and in the Operations window (no limit, or 1, 2, 5, 10, 25, 50 or 100 MB/s), and a job that is still waiting has a _Priority_ menu (High, Normal, Low). The tighter of the global and the job's limit holds, a new limit reaches a running copy within a fraction of a second, and the polite live region says the change. When a slot frees up the waiting job of the highest priority starts, and equals in queue order; a running job is never stopped for a higher one. A limit paces writing only: the copied bytes, the checksums and the read-back of a verified copy are the same, and a copy under a limit does not use a server-side or reflink shortcut. A job's own limit and priority last as long as the job (a restart does not resume jobs); the global limit is a setting and is exported with the others.
- **Scheduling and Pause all (D157):** a job that has not started has a _Schedule…_ button on its row (status bar popover and Operations window) that opens a small form: _Start at_ a date and time, or _Only between_ two times of day (a window may run across midnight, as 22:00 to 06:00). _Set schedule_ keeps it, _Run now_ clears it, Escape closes the form, and the form tells in words when a time has passed or the two times are the same. A scheduled job waits in the queue as "Scheduled for …" or "Scheduled between … and … each day", takes no slot, lets other jobs pass it and starts by itself when its time comes (a start time that has passed means now); once started it is not stopped when its window ends. Scheduled jobs are saved and queued again when Waypoint starts; a job that is not scheduled is not (a restart does not resume jobs). A scheduled job that starts while no Waypoint window has focus notifies, as a finished one does. **Pause all** / **Resume all** (one toggling button in the Operations list header, the File menu and the command palette, enabled only when something runs or is paused) pause every running job at its next chunk and hold back the queue, and resume them; the list says "Paused: nothing starts until you resume." while Pause all is in force. A job waiting for an answer keeps waiting.
- **Copy, move and paste:** Paste, Copy To…, Move To… and F5 and Shift+F5 each submit one job (copy, move, or duplicate for a copy beside the originals) from the selection or the clipboard, with no conflict policy chosen, so the conflict resolver asks before anything is overwritten. A paste into a folder inside what is pasted, or a cut onto its own folder, is refused with a message before a job is queued; the planner refuses the same cases when a job reaches it. Undo for a finished copy or move is the queue's toast. The clipboard is Rust's and is shared by every window (§13b).
- **Safe writes:** a copy or move writes each file under a hidden temporary name beside its destination and renames it into place, so a name never holds half a file, and a cancel or failure removes what it wrote. A move on one drive is a rename; across drives it copies and then removes each item as soon as its copy is complete, so stopping part way leaves every item either moved or untouched.
- **Links:** a link job makes a symbolic link in the destination to each source (by its absolute path), named like the source, or `Link to name` when it is made beside the source. Clashes are decided like any other, and a link can replace a file or another link but never a folder. On Windows making a link needs the privilege to, and without it fails for each item with that reason.
- **Conflict resolver:** before anything is written, one dialog covers the whole batch. Each clash is shown with its sizes and dates, with per-file or apply-to-all choices: Replace, Skip, Keep both (rename), Merge folders, or Replace if newer. Nothing is overwritten without a choice, and the default button is never Replace. As built (milestone 4, slice 09): the dialog is titled “N items already exist in {destination}” (a restore says “in their original folders”) and lists each clash with the existing and the incoming entry side by side — kind, size and modified time (in the system 12 or 24-hour clock) — and, for two files, a text hint that the incoming one is newer, older or the same date. Each row has its own choice, limited to what can be carried out: Replace, Skip, Keep both or Replace if newer for two files; Merge folders, Skip, Keep both or Replace for two folders (Replace says it replaces the whole folder); only Skip and Keep both for a file against a folder, with the reason shown. Nothing is pre-selected and Continue stays off until every clash has an answer of its own or “Apply to all remaining” reaches it; “Apply to all conflicts like this one” makes that choice the job’s own, so clashes met later (inside a merged folder) are settled the same way, and without it they ask again in a dialog of their own. Keep both says the new entry is kept as a numbered copy (a restore says it is restored under a free name). A list of more than 200 clashes draws the first 200 with “and N more” and a Show all button, and the bulk choice covers the rest. Focus starts on the first control; Cancel the operation stops the job (after a confirmation once anything has been answered), a click outside does nothing, and Escape or Decide later closes the dialog and leaves the job waiting in the queue, where Resolve… opens it again from any window. The dialog opens by itself in the window that started the job; another window answering first closes it. An item that stops a job shows a second dialog that says what went wrong, which item and which job, with Retry, Skip, Skip all like this and Cancel the operation (and Recreate folders for a restore whose original folder is gone); Escape there closes it and leaves the job waiting. **Previews (milestone 5, slice 20).** For two files each side shows a thumbnail where one can be made (images, video and documents on local files, as everywhere else; the file type icon otherwise) beside its kind, size and modified time, and the incoming side says in words whether it is newer, older or the same date and whether it is larger, smaller or the same size (never by colour alone). The dialog also compares the two files' contents: the first twelve rows do it by themselves, two at a time, and any other row has a "Compare the files" button. It says "Identical contents. Skip is probably what you want." when the bytes are the same (the default is not changed: nothing is chosen for you, and Replace is still never the default), that the files differ and are not text, or that they are too large to compare (over 256 KiB each). For text files up to 256 KiB each it counts the lines added and removed and opens, with "Show differences", a compact unified diff: a line number, a + or − sign and monospace text, three lines of context around each change with a note where unchanged lines were left out, the first 200 rows and then "N more lines". A screen reader hears each row as "Added, line 4: …", "Removed, line 2: …" or "Unchanged, line 1: …". Only two files that both exist are compared: a folder, a clash inside the batch and a location whose provider cannot be read (a remote one) show no comparison, and a comparison that fails shows nothing, so the dialog works exactly as it did without previews. Keyboard operation is unchanged apart from the extra buttons. Replace if newer replaces a file only when the source is clearly newer (equal dates keep the existing file). A file and a folder with the same name can only be skipped or kept both. Merge folders decides the clashes inside by the choice made for all, and asks about any it cannot settle; inside a merge, Replace overwrites files and merges folders, so it never empties a folder. Replace chosen for all never replaces a whole folder either: folders it meets are merged, and only a Replace answered for that folder replaces it. A file or folder that clashes with one the same job has just placed on a case-insensitive destination (a folder holding both `A` and `a`) is kept under a free name instead of replacing it. A failure during the run (permission denied, disk full) offers Retry, Skip, Skip all (every later failure of the same kind) or Cancel; one bad file does not stop a folder, and what was skipped is listed when the job ends.
- **Checksum verification:** a setting, off by default, that verifies after each copy (BLAKE3 by default, or SHA-256). Each file is read back, and its source read again, before it is put in place and before a move removes the source; a mismatch fails that item and nothing half-written is left. Results are recorded on the job.
- **Undo/redo:** Ctrl+Z and Ctrl+Shift+Z for new items, rename, duplicate, move, copy (deletes the copies), trash (restores), and batch rename; tag changes join in a later milestone. Undo refuses, and says why in plain words (something is no longer there, has changed, its name is taken, or is no longer in the Trash), when the files have changed since; with nothing to undo it says so. The history is kept across restarts (the last 50 operations, shared by all windows), is listed in the Edit menu, the application menu and the command palette, and any entry can be undone from there. If Waypoint stopped in the middle of an operation, the next start says so; it never resumes by itself.
- **Trash:** moving to the Trash is undoable and, on Linux, shared with the other file managers. The Trash place lists what is in it (on every volume) with its original location and deletion date, and offers Restore (to the original location, asking when the name is taken), Delete Permanently and Empty Trash, with an optional "Empty items older than N days". On Windows it is the Recycle Bin. The Trash view is a read-only list with the columns Name, Original location, Date deleted and Size; Restore, Delete Permanently and Empty Trash are in the item menu, the background menu, a slim action bar above the list and the sidebar item's menu. Delete Permanently (the Delete key) and Empty Trash always ask first. The list takes keyboard focus when the Trash opens, so the arrow keys, Shift+arrows and Ctrl+A select, Ctrl+Shift+R restores the selection, and Restore and Delete Permanently are also commands in the palette. Enter on an item does not open it and shows a hint, and New Folder, Rename, Paste and drop are not offered. When the original name is taken, Restore asks: Keep both (restores under a free name), Skip, or Replace (files only); when the original folder is gone it offers to recreate it. The "Empty items older than N days" sweep runs once at start-up, after the window is shown, is off by default and is an ordinary job in the queue; its setting is `trash_expiry_days` in the operations settings, which the Settings window owns once it lands.
- **Batch rename:** Ctrl+F2 opens a dialog with a stack of rules applied in order to every selected entry, and a live before and after table. The rules are find and replace (plain text or a regular expression with `$1` groups, matching case or not, the first match or all), a counter (start, step, digits, before, after or instead of the name), case (upper, lower, title, sentence), a date from the modified time, the created time or today (`%Y %y %m %d %H %M %S`), insert text, remove characters, trim spaces and change extension. A rule works on the name without its extension unless it is aimed at the whole name or the extension, so extensions are kept; a note says when a rule changes one, and a folder has no extension. A rule that cannot work (a pattern that does not compile, a date format with an unknown token) is shown under that rule and counts as a problem. Each row shows its new name, and a row that cannot be used says why in words: the name is not allowed (on Windows that includes reserved names and a trailing dot or space), two entries would get the same name, or another entry that is not being renamed already has it. Apply stays disabled until nothing is wrong and at least one name changes; the summary line says how many problems there are. Swaps and chains are fine (`a`→`b` while `b`→`a`, or `a`→`b`, `b`→`c`), and so is a change of case alone on a drive that treats the two as one name: Waypoint renames through temporary names and never overwrites anything. The job is all or nothing: every name is checked before the first rename, and if a rename fails or the job is cancelled part way, the ones already done are put back. It is one entry in the undo history ("Rename 12 items"), and one undo puts every name back. Rename rule plugins add tokens.

## 9. Theming & platforms

Full detail is in `docs/theming-and-platforms.md`.

- **Modes:** Light, Dark and System. There's also a Theme source: Liminal (the brand tokens) or OS (the portal accent, colour scheme and icon theme).
- **Icons:** file and folder icons come from an icon set, chosen on Settings → Appearance → Icons: **Waypoint** (the app's own outline set, the default, the same on every system) or **Portage** (a coloured set of flat shapes), or **System** (the icons the operating system itself shows, as its own file manager does: on Linux the file type and folder icons of the user's GTK icon theme, such as Adwaita, Breeze or Papirus, and on Windows the shell's icons for each file type and for folders and drives), which the picker offers only where the system can supply them and otherwise explains why it does not (no display, no icon theme installed, a Flatpak sandbox that cannot see one). The System set draws a file by its type (its extension, or a stand-in type for a file with none) and a folder by its kind (the user's standard folders get the theme's own Documents, Downloads, Pictures and the rest, any other folder the plain folder), so a folder of ten thousand files asks the system for a handful of pictures, not ten thousand. Waypoint's glyph is drawn while a System icon loads and for any type or folder the theme has no icon for, so an icon is never blank, and the icons repaint when the system's icon theme or its light or dark mode changes. The Icon style and Folder colour rows do not apply to System (the style is the Waypoint set's and the colours are Portage's): the style row is dimmed and the colour row is replaced by a note that says so. The picker shows each set with a preview strip (a folder, an image, a PDF, a document and an archive) drawn by that set, and the change applies at once in every window, to the lists already on screen. Waypoint's set has a glyph for each kind of file (PDF, spreadsheet, shell script, font, disk image, certificate, e-book, 3D model, package, symbolic link and more, see §5.5) and a marked folder for each of the user's standard folders. The **icon style** is Light (a thin 1 px stroke), Regular (the default), Bold (a 2 px stroke) or Filled (Regular's stroke with every closed shape tinted: a folder in a stronger accent, other shapes in a tint of the icon's own colour; open strokes such as chevrons, arrows, check marks and lines stay unfilled). It draws every outline icon of the Waypoint set at once and live: the file and folder glyphs, and the toolbar, menu, Inspector, Shelf, Devices, queue and window chrome glyphs. The row shows each style as a strip (a folder, a file and three toolbar and menu glyphs) drawn in that style, and under high contrast no style draws a stroke thinner than 1.6 px, so Light and Regular are lifted to it and Bold stays as it is. Portage is coloured art and ignores the style, so the row is dimmed while Portage is chosen (and the toolbar, menu and chrome glyphs stay Regular then too). Portage folders come in ten colours (Liminal, GNOME, Cinnamon, KDE, Windows 11, Red, Pink, Orange, Purple and Rainbow), picked from a row of named swatches that shows only while Portage is chosen, and each colour has a deeper shade for light mode and a softer one for dark mode that follows the window's resolved mode. Portage draws no drop shadow under its icons. The icon set is a choice for file and folder icons only: toolbar, menu and chrome icons are always Waypoint's own outlines, drawn in the chosen icon style.
- **Match the system's colours:** Settings → Appearance → Colours has a switch, off by default, that draws Waypoint's surfaces, text, selection, borders, focus ring and warning, error and success colours in the palette of the desktop's own theme instead of Waypoint's own. The palette comes from the GTK theme's named colours on GNOME, Cinnamon, MATE and Xfce, from `kdeglobals` on KDE and from `UISettings` (and the user's own colours in a high-contrast theme) on Windows. It describes one variant, so in System mode the window takes the variant the palette is (a dark theme makes a dark window whatever the colour-scheme setting says), and a mode forced to the other variant keeps Waypoint's colours, with a note saying so. Every pair is held to a floor: text and the selected row's text 4.5:1 on the surfaces they sit on, the status colours 4.5:1 and the focus ring 3:1; a colour that falls short moves to the nearest one that passes, and the page lists what it adjusted. The accent keeps its own setting and rule below, and high contrast, forced or the system's, ignores the switch (the page says so). Where the system offers no palette the switch is hidden and the Services panel says why (a GTK theme with no `theme_bg_color`, no `kdeglobals` colours, macOS). It applies at once and follows the system's theme changes.
- **Accent contrast:** the text on the accent colour always keeps 4.5:1. The light theme fills with `#c2410c` under white text and the dark theme with `#f97316` under near-black text; an accent chosen by the OS or the person gets black or white text by contrast and its fill is adjusted when neither reaches 4.5:1. The bright orange stays for focus rings and borders (3:1).
- **Applying it:** Rust reports the OS preferences and the page sets them as attributes on each window; no media query is the only signal, because the Linux webview does not report them reliably.
- **Transparency:** the main setting, off by default, labelled Experimental on Linux. It makes the window's backgrounds translucent, with an opacity slider for each part of the window (40 to 100 %: title bar and menu bar, tabs and toolbar, sidebar, file area), blur where the platform has it (Off, Low or High: Mica and Acrylic on Windows, the compositor's blur on KDE), per-part control (title bar and the rows under it, sidebar and panels, file area), translucent menus with their own opacity, and "Solid when unfocused". Opacity works wherever the platform reports that windows can be see-through; blur works on KDE and Windows, and on GNOME its row is hidden with the reason shown on the page and in Services. It is off under high contrast or reduced transparency, a part is never more see-through than keeps its text at 4.5:1 over a bright or dark wallpaper, and the page shows a live preview that follows the sliders as they are dragged.
- **Languages and direction:** English (Canada) and Français (Canada) ship, both complete (the French is written in Québec usage, with a glossary in `docs/translating.md`), and the language setting is System default (the nearest of those to the OS language, English when there is none) or one of them. Messages are one catalogue per language, loaded when a window starts, with English filling in any message a catalogue lacks; dates, numbers, sizes and relative times follow the chosen language, or the OS locale for System default. `lang` and `dir` are set on every window's root, and a right-to-left language mirrors the layout, the arrow-key directions and the back, forward, chevron and undo glyphs (see `docs/accessibility.md`). Developer builds also offer two pseudo-locales, English with accents (`en-XA`, about 30% longer) and a right-to-left mock (`ar-XB`), for checking text expansion and mirrored layout; release builds neither list nor load them. A language is translated as a JSON file (`translations/<locale>.json`, one entry per message with a note for the translator and the hash of the English it was translated from) that a command turns into the catalogue; a message whose English has changed is flagged as needing review, a plural group holds the forms the language's number rules need (Polish has few and many), and the build fails when a language that is meant to be complete has a missing, stale or extra message. Translators can use a browser tool or edit the file; see `docs/translating.md`.
- **DE frames:** the prototype shows Waypoint on **GNOME** (libadwaita), **Cinnamon** (Mint-Y, Nemo's home), **KDE Plasma** (Breeze) and **Windows 11** (Mica/Fluent, as a portability check).

## 11. Settings

Settings open in a separate window using the same side-nav pattern as Emoji Nook, from Ctrl+, in any main window (the application menu and the command palette add their own entries). Every change applies at once, with no Save button; a value Rust refuses is explained under its row and the row keeps the value in force. A page that is not built yet does not appear. The window ships in milestone 4 with the General, Operations and Drag & drop pages; each other page arrives with the milestone it belongs to (Appearance, Transparency, Previews & thumbnails, Accessibility and Language & Region in milestone 5; Integrations in milestone 7; Plugins and Developer in milestone 8; Privacy in milestone 9; Keyboard and Tabs & windows in milestone 10).

1. **General:** startup (restore session or open Home; the "Open startup tabs" list arrives later), default view, single or double click, confirm on delete (off by default for the Trash; Delete Permanently always confirms), hidden files. _Built in milestone 4:_ **When Waypoint starts** (restore the last session, or open one window at Home; read when the app starts), **Default view** (list or grid) and **Show hidden files by default** (both apply to windows opened afterwards; open windows keep theirs), **Open items with** (single or double click; changes at once in every window; a single click never opens on Ctrl or Shift, or in a rename field) and **Confirm before moving to the Trash** (off by default). **Remember each folder’s view** (on by default; see §5.3b; takes effect at once in every window). **Show Git status** (on by default; see §5.3b; takes effect at once in every window and turns the Git column, the marks, the branch, the sidebar's dots and the Inspector's Git tab off). **Back up and restore** (a group at the end of the page): **Export settings…** saves your settings to a file you choose, named `waypoint-settings-` and today's date by default (`.json` when one set of settings is exported and `.zip` when there are several; today the application settings, the operations settings, the remembered folder views and the saved connections are four, so the file is a `.zip`; the folder views list one change per folder added, changed or forgotten, and the saved connections one per connection and one for the recent servers; a remembered password stays in the keyring and is never exported), and says where it went; **Import settings…** reads such a file and, before anything changes, lists what would change by page and how many values, and anything it will leave out (settings from a newer Waypoint that this version does not have), then asks **Replace my settings** or Cancel, with Cancel the default. Replacing is all or nothing and applies at once in every window; the settings it replaced are kept as the previous copy. A file that matches what is in force says so and changes nothing. A file that is not a Waypoint settings file, is damaged, was made by a newer Waypoint, is larger than 1 MB (4 MB for a whole archive), is an archive with entries Waypoint will not read, or holds a value a normal change would refuse (the setting is named) is refused, and the reason is written under the row. Nothing outside the settings is exported: the session (windows and tabs), the undo history and caches stay behind.
2. **Appearance:** mode, theme source, accent, match the system's colours (where the system has a palette), density, icon theme (Waypoint, Portage or System), folder colour and icon style, thumbnail size.
3. **Transparency:** enable, an opacity per part of the window, blur, per-region toggles, translucent menus and their opacity, "Solid when unfocused", a "Reset to defaults" button (every setting on the page but the enable switch) and a live preview.
4. **Accessibility:** high contrast, text size (100, 115 or 130 %), touch mode (Off, Auto or On; Auto is on when the last pointer was touch or no fine pointer exists), reduced motion, reduced transparency, and a stronger focus ring. Each one follows the OS or is forced on or off.
5. **Language & region:** language (System default, English (Canada) or Français (Canada); the pseudo-locales in a developer build) and direction (Automatic, Left to right or Right to left). A change applies at once in every window: the new catalogue loads first and the window then redraws in it. There are no separate date, number or first-day-of-week overrides; formats follow the language.
6. **Tabs & windows:** new-tab location, middle-click behaviour, tear-off, close last tab behaviour, groups.
7. **Drag & drop:** default action rule, spring-load delay, the Shelf (persist it, auto-hide), terminal drop behaviour. _Built in milestone 4:_ **Default drop action** (move on the same volume and copy otherwise, always copy, or always ask; Ctrl, Shift and Alt still decide when held), **Spring-load delay** (200 to 2000 ms, 600 by default, one delay for folders, tabs and sidebar items) and **Keep the Shelf between sessions**; when the system cannot drag files out to other applications the page says why. The drag engine and the Shelf read these settings when they arrive in later slices.
8. **Previews & thumbnails:** file types, max file size, remote thumbnails, folder peeks, hover-to-peek, and whether Overview measures Home when it opens. _Built in milestone 5 (slice 9):_ **Show thumbnails** and **Largest file to make a thumbnail of** (1 to 2048 MB, 50 by default); when the system cannot make thumbnails the page says why in the plugin's own words and shows neither. Folder peeks and hover-to-peek arrive with the features they switch. _Built in milestone 5 (slice 25):_ **Measure Home when Overview opens** (on by default; off means Overview measures Home only when you choose Measure now), shown even where thumbnails are unavailable.
9. **Operations:** verify after copy, algorithm, concurrency, undo history depth. _Built in milestone 4:_ **Verify copies after writing** (off by default), **Checksum algorithm** (BLAKE3 or SHA-256, available while verification is on), **Operations running at once** (1 to 8, applies to the next operation), **Undo history depth** (1 to 200) and **Empty old items from the Trash** with **Delete Trash items older than** (days; off by default, runs when Waypoint starts). **Archives** (milestone 6) sets the limits an extraction keeps to: **Most entries in an archive to extract without asking** (1 000 to 100 000 000), **Most an archive may expand to without asking** (1 to 1 024 GiB), **Most times its size an archive may expand to** (10 to 100 000) and **Check the expansion ratio only above** (1 to 1 048 576 MiB), with a **Reset to defaults**.
10. **Keyboard:** the shortcut editor, a Vim mode toggle and a keymap preset (Nemo, Dolphin, Finder-like).
11. **Integrations:** the Services panel (every native plugin and each remote protocol, what works and why not, with "Turned off in Settings → Experimental" for a protocol whose switch is off; the keyring is listed as _Keyring and saved passwords_ and says whether none is running or it is locked), then notifications, dock or taskbar progress, prevent sleep, the global shortcut and the default file manager, all off until enabled (milestone 5); the terminal emulator, Flow and "Open with" defaults arrive later. _Built in milestone 5 (slice 19):_ **Notify when a job finishes**, **Show progress on the app icon**, **Keep the computer awake during jobs**, **Make Waypoint the default file manager** (a button, with who is the default now), **Open folders other applications ask for** (Linux), and **Bring Waypoint forward with a shortcut** with an editable **Shortcut** field (`Ctrl+Alt+W` until changed). A switch the system cannot do is dimmed with the reason the Services panel gives. **Show buttons on notifications** sits under the notification switch and is hidden where the system cannot take buttons (D139).
12. **Experimental:** the remote protocols' switches (D167): **SFTP**, **SMB**, **WebDAV** and **S3**, each off by default and marked Experimental, with one line on what it enables. _Built in milestone 6:_ a switch takes effect at once, for all four protocols; one for a protocol this build does not include is dimmed and says so.
13. **Plugins:** a link to the Plugin manager.
14. **Privacy:** recent files, search index scope.
15. **Developer:** see §12. It's hidden until you enable it (click the About version 5× or pass `--dev`).

## 12. Developer options

- **Inspector overlays:** show drop target outlines, drag regions and the focus ring trail.
- **Plugin dev:** load an unpacked plugin from a folder, hot reload, a log console per plugin, an API playground and the permission audit.
- **IPC and backend:** a live IPC log, FS watcher events and provider latency charts.
- **Theme tools:** a token inspector, forcing a DE frame or colour scheme, and a portal-values dump.
- **Feature flags:** experimental toggles.
- **Diagnostics:** export logs and reset settings.

## 13. Integrations

- **Terminal drawer:** a bottom drawer running the user's shell that follows the active pane's cwd (an optional setting). You can drop files into it and pop it out to an external terminal.
- **Flow:** logs your working context (current workspace, recently touched folders) to Liminal Flow. Opt-in.
- **Session restore:** the next start brings back each window with its size (and position, where the platform lets an app place its windows: not on Wayland), its tabs in order with the active tab and each tab's back and forward history, the list or grid view with its icon size, hidden-files choice, sort and grouping, each tab's scroll position and focused entry, and Recently Closed. Closing a window waits about 150 ms before it goes, so the page can report each tab's scroll position and focused entry first and they are saved with the session. A folder that no longer exists opens as the usual "Folder not found" page with its history intact. A session file that cannot be read is kept aside, the previous run's copy is tried, and the status bar says "Your last session could not be restored" if neither works. Closing the last window by its own close button keeps that window's tabs for the next start; closing its last tab instead (or closing other windows) sends the tabs to Recently Closed. Groups, splits and selection are restored with their own features.
- **Devices:** mount, unmount, eject and unlock LUKS volumes (passphrase dialog, remember in keyring).

## 13a. OS integration

Full detail in `docs/os-integrations.md`. Portals first, so Waypoint works as a Flatpak. It shares Trash, thumbnails, bookmarks, recent files and tags with other Linux file managers, reads Nemo, KDE and Nautilus actions, and integrates with notifications, dock progress, a global shortcut, sleep inhibit and the default-file-manager setting. Windows 11 is a real target with its own equivalents (Recycle Bin, jump lists, Explorer menu, Quick Access, OneDrive placeholders). Options that don't work on the current system are hidden; Settings → Integrations has a Services status panel.

- **Notifications:** off until enabled. A job that finishes or fails notifies when no Waypoint window is in front or it ran for more than 10 seconds; a job that stops to ask you something always notifies; a cancelled job never does. The notification carries the job's own title (“Copy 3 items”) and what happened, and clicking it brings the most recent Waypoint window forward. Where the system draws them, it also carries up to three buttons (the **Show buttons on notifications** switch, on by default): **Show in folder** when a job finishes, plus **Undo** after a move or a trash while it is still the newest thing the undo journal would undo; **Show details** when it fails; **Replace**, **Skip** and **Keep both** for a single file that already exists (this item only, never “apply to all”); and **Show** for any other question. A button for a job that has gone opens the Operations window. Some desktops draw the buttons only when the notification is expanded and some show only the click, which is why the click always does something sensible.
- **Progress:** off until enabled. One value over every job in flight shows on Waypoint's dock or launcher icon (Linux) or its taskbar button (Windows): a moving bar by bytes (by items where a job has no sizes), a busy bar while a job is still being planned, and nothing when idle.
- **Keep awake:** off until enabled. While a job is planning, running or stopping, the computer is kept from going to sleep; it is let go as soon as none is, and when Waypoint quits.
- **Default file manager:** the Settings button makes Waypoint the default for folders where the system lets an application do that (Linux, from an installed Waypoint), and on Windows opens Default apps, where you choose it yourself. With **Open folders other applications ask for** on (Linux), another application's “Show in folder” opens the folder in a new tab, and “Show item” opens its folder with the item selected.
- **Global shortcut:** off until enabled, `Ctrl+Alt+W` until you type another (at least one of Ctrl, Alt, Shift and Super, then one key). It raises the Waypoint window you used last, or opens a new one. On Wayland the desktop asks you to confirm the shortcut, and a changed shortcut applies the next time Waypoint starts.

### 5.9 Action bar

A row below the toolbar (on by default, hideable) with common commands. It ships in milestone 4 with New (a menu of Folder and File), Cut, Copy, Paste, Rename, Delete (moves to the Trash), Sort (a menu of the sort keys, Descending and Folders first, then the groupings), View (switches between List and Grid), Undo and Redo, and gains Extract all (only inside an archive, beside Delete: it extracts the whole archive into a new folder beside it) and, as those features arrive, Share and Group. Each button is the same command the menu and the key run, on the active pane: a button whose command cannot work in this location is left out (the Trash has no New, Cut, Copy, Paste, Rename or Delete) and one that needs a selection, a clipboard or a history is disabled and says why in its tooltip. Tooltips carry the key. Labels are shown by default. Right-click the bar (or press the Menu key or Shift+F10 on it) to hide the labels or hide the bar; View → Action Bar brings it back. Both choices are Rust's (`ui.actionBar` and `ui.actionBarLabels` in the settings document), so every window and every restart agree. The bar is a toolbar with one tab stop: Left, Right, Home and End move along it, the Down arrow opens a menu button. When the window is too narrow the trailing buttons move into a More menu. Adding, removing and reordering items and plugin buttons come later. Also togglable from the View menu (the command palette will list it too).

## 13b. Customisation and basics

- **Keyboard shortcuts:** an editor lists 17 common actions; click one and press the new keys. Conflicts are caught and named. Start from a Waypoint, Nemo, Dolphin or Explorer set.
- **Context menu:** choose which file-menu items show and reorder them.
- **Icon style:** Light, Regular, Bold or Filled for the Waypoint icon set's own icons: file and folder, toolbar, menu and chrome (it does not apply to Portage; see §9).
- **Window layouts:** save the tabs, pairs, groups and panes as a named layout and restore it later.
- **Shared clipboard:** copy or cut in one window and paste in another, including the floating window: one clipboard, kept by Rust, that every window follows. Copy and Cut also put the files on the system clipboard (where the system allows it: `native-dnd` reports it), so files copied in Waypoint paste into other file managers and the reverse. A paste, and a window gaining focus, look at the system clipboard first: files another application copied since are adopted, as a copy or as a cut as that application says; the same files as Waypoint's own, anything that is not files, and files already seen are ignored. Where the system clipboard is unavailable or refuses the write, Waypoint's own clipboard still works between its windows.
- **Compare and Sync:** for a pair of tabs, list files that differ or exist on one side, choose copy left, copy right or skip for each, then synchronise as background jobs.
- **Previous versions:** in Properties, restore a file from a snapshot as a copy.
- **Terminal history:** commands are remembered per workspace.
- **Help** (built): F1 anywhere in a main window, or Help ▸ Help, opens a dialog with a small animated picture (still under reduce motion) and a few keys worth knowing, each read from the command registry, with buttons to the shortcut list, the tour and About. **Keyboard Shortcuts** (`?`, or Help ▸ Keyboard Shortcuts; `?` is ignored while typing in a text field and in the middle of a name typed to jump in a list) lists every command the window offers that has a key, grouped as the palette groups them; a command the window hides is left out. **Take the Tour** is five steps — Welcome, Tabs are workspaces, Drag and drop everywhere, Commands, Works with your desktop — moved through with Back and Next (Skip, Esc and Get Started close it), and is never opened by itself. **About Waypoint** shows the version, the licence (Apache-2.0 OR MIT) and what Waypoint is built with. All four are also palette commands. Later: opening the tour on first run, a search row once search exists, and an update check and channel in About once there is an updater.
- **Updates:** a stable or beta channel in About, check for updates, install and restart (planned; About shows the version and licence now).
- **Privacy and crashes:** crash reports are offered, never sent silently, with three levels of detail; no usage analytics.
- **Touch mode, language and direction, text size, high contrast, focus ring, reduced motion:** Settings → Accessibility and Language & region (languages and pseudo-locales in §9). See `docs/accessibility.md` for the review.

## 13c. Tab drag language

Every tab drag shows one label pill beside the pointer saying what will happen, with “Esc to cancel”. Motion is 140 ms and turns into instant jumps with Reduce motion. The thresholds are one set (`apps/waypoint/src/tabs/dragTiming.ts`): a drag starts after 4 px of movement, tears off only once the pointer leaves the window, splits after a 450 ms hold over the middle half of a tab, and starts a group after an 800 ms rest in a slot (moving more than 6 px starts the hold over). The pill is also read through the live region (“Drag: release to …”), and the result after the drop (“Added Docs to Work, now 3 tabs”); Esc says “Drag cancelled”. Every outcome has a menu or key route too (see SPEC §5.2), and nothing here is the only way to do anything.

- **Reorder:** the tab follows the pointer inside the strip, the other tabs slide aside, and a thin accent line marks the open slot. The pill says “Release to move Docs to position 3 of 5”. A pinned tab stays among the pinned tabs and an unpinned one outside them; a pair moves as one (drag either half or the joint) and a group moves by its chip (“Release to move group Work”).
- **Split pair:** hold over the middle half of another tab. A ring draws around it over 450 ms, then the two tabs bridge into one pill and the pill says “Release to split with Music”; releasing joins them, in the order they were dragged. Offered between two tabs that are not paired, have the same pin, and are in the same group (or the dragged one is in none, and joins the other's group).
- **New group:** rest in a slot for 800 ms. A bracket draws under the slot and the pill says “Release to start a new group”. The tab lands in that slot and the group is made with the tab before it (or after it, at the start of the strip); the neighbour must be ungrouped and share the pin. The new group opens with its name ready to edit.
- **Add to a group:** drag onto a group label (the pointer over the chip); the pill says “Release to add to Work”.
- **Leave a group:** drag the tab until its centre is past the group's span, the chip included; the pill says “Release to leave Work” and the tab lands where the line shows, outside the group.
- **Split pane:** drag into the file area (the panes, not the sidebar, toolbar or status bar). The whole area shows four labelled regions with dashed outlines: “Split left” (its left third, full height), “Split right” (its right third) and, in the centre column, “Split top” and “Split bottom” (its upper and lower halves). The region under the pointer turns solid accent and the half of the area the new pane would take is tinted; the pill says “Split top with the current view” (left, right, bottom) with “Esc to cancel”. Releasing joins the dragged tab with the view on show: its folder opens beside it, on that side. Dragging the active tab itself is allowed and splits it as F3 does, with a copy of its folder in the new pane. Only for a view that is not in a pair, with a tab that is not in one either, and the same pin and group rule as above. Left and right make a side-by-side pair and top and bottom a stacked one, with the dragged tab in the first pane for left and top. The regions are measured once when the drag starts. Leaving the area, or Esc, cancels the regions (a few pixels of slack stop the border from flickering); over the strip, the toolbar, the sidebar or the status bar the drag is a plain reorder and never a tear-off.
- **Separate:** drag a pane header's grip up to the strip; the pill says “Release to separate the split”.
- **New window:** drag out of the window: the pointer's position is outside its client area (or the document reports the pointer left it). Inside the window, over the strip, the toolbar, the file area or anywhere else, nothing tears off. The tab collapses out of the strip, a mini window preview (the first tab's folder, and a count for a pair or a group) is shown at the pointer's last position in the window until a ghost or the compositor's window takes over, and the pill says “Release to open in a new window”. Where the system reports a live cursor (X11 and Windows) the preview carries on as a floating ghost outside the window, and a release opens the new window with its top left under the pointer; the result is announced (“Moved Docs to a new window”). Moving back into the window, or Esc, cancels, and a drag the system lost track of for 30 seconds ends and says so. Dragging one half of a split by its pane header's grip works the same way and takes that tab alone.
- **Merge:** where the system can find another Waypoint window under the pointer (X11 and Windows), the ghost's label becomes “Release to merge into Documents” while the pointer is over that window's tab strip. Releasing on the strip adds the tabs (a tab, a split or a whole group) at its end; releasing on the left or right half of one of its tabs puts them before or after that tab. The tabs keep their history, pin, colour and state, the window they left closes if they were its last, and the result is announced (“Merged Docs into Music”). The window under the pointer shows where the tabs will land: the strip gets a faint highlight and the same accent line as a reorder, between two tabs, at the edge of a group or a split pair (a slot inside one lands after it), on the pinned side of the pinned boundary the tabs belong to, or at the end, and the tabs land exactly where the line was. A screen reader hears once, politely, “A tab is being dragged here: release to add it at position 3”. The line goes when the pointer moves off, on release or cancel, when the window loses focus, or when no update has arrived for a moment. A release over the window the drag began in is not a merge.
- **Wayland with `xdg-toplevel-drag`:** the compositor reports no cursor position and no window positions, so there is no ghost, but it can move a real window for the app. Pulling a tab, pair or group out of the window moves it to a new window straight away (a window that holds only the dragged tabs is dragged itself), and that window follows the pointer outside every window, with no card or pill in the page. A release over another Waypoint window merges the tabs there and the emptied window closes: the other window shows the line at the slot under the pointer on its strip (over the rest of the window the tabs go to the end, and the line is shown there), and the tabs land at that slot; a release over nothing leaves the window where it was let go; Esc, or any failure, puts the tabs back where they were (they stay in the new window if their old window is gone). Each ending is announced.
- **Wayland without it (and as the fallback):** the preview and the pill stay inside the window, a release outside the window opens a new window the compositor places (the pill reads the same), and merging into another window is Move to Window ▸ on the tab, group or split's menu. Nothing in the interface announces the difference; Settings → Integrations → Services will list what the system cannot do.
- **Cancel:** Esc at any point slides the tab back to where it started. So does the browser taking the pointer, or the session changing under the drag (a tab closed in another window).

## 14. Accessibility

Every action works from the keyboard, focus is always visible, and screen readers get labels and live regions for ops progress. Waypoint follows reduced motion (no spring animation), reduced transparency and high contrast. Hit targets are at least 28 px on desktop and at least 44 px in touch mode. Text contrast meets WCAG AA on every theme, including transparent windows, where text falls back to a solid backdrop when the measured contrast is too low.

## 15. Success criteria (design)

- Common tasks work without the mouse and without looking anything up.
- Moving a file from local to a remote folder in a different tab takes one drag, whether through a spring-loaded tab or the Shelf.
- A new user recognises Waypoint as belonging to the same family as Jar and Threshold.
- The same window feels native in all four DE frames.
